# CyberGarden · ВИНИТИ РАН

Локальный прототип для направления «RAG и поиск по документам». Загрузите научную статью, найдите метрику и откройте страницу с подсвеченным источником. JSON сохраняет исходную цитату, значение и координаты для последующей обработки.

## Запуск

Нужен Python 3.12 с модулями `pip` и `venv`. На Linux их можно установить через пакетный менеджер своего дистрибутива, если они отсутствуют.

### Linux и macOS

```bash
git clone https://github.com/ichirou-hue/cybergarden-viniti.git
cd cybergarden-viniti
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

Для клонирования нужен доступ к приватному репозиторию. Если Python 3.12 установлен под именем `python3`, проверьте версию через `python3 --version` и используйте этот исполняемый файл.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). После установки пакетов приложение работает офлайн. База по умолчанию создаётся в `data/papers.sqlite3`. Параметры `--port` и `--db` меняют порт и путь к базе.

### Новый каталог результатов (заглушка API)

Каталог публикаций, карточка статьи и просмотр доказательств работают на мок-API: он отдаёт и статику, и заглушки эндпоинтов `/api/documents…`, повторяющие контракт из `docs/adr/0008-rag-catalog-ui.md`.

```bash
.venv/bin/python tools/mock_api.py --port 8799
```

Откройте [http://127.0.0.1:8799](http://127.0.0.1:8799). `server.py` — точка входа прежней версии: он пока не отдаёт ES-модули нового интерфейса и эндпоинты `/api/documents`, поэтому до подключения backend Мити каталог запускается только через `tools/mock_api.py`.

### Пакетный разбор

```bash
.venv/bin/python analyze_pdfs.py articles/*.pdf -o results.jsonl
.venv/bin/python -m unittest -v
```

В PowerShell используйте `.\.venv\Scripts\python.exe` и укажите PDF отдельными аргументами. Пакетный разбор работает без сервера. Он записывает по одному JSON-объекту на успешно разобранный PDF в новый файл. Ошибки выводятся в stderr, а итоговый код 1 означает, что часть входных файлов обработать не удалось. В новых результатах есть SHA-256 исходного PDF и версия извлечения в `extraction`.

UI-проверки каталога (dev): `cd tools/uitest && npm install && node harness.mjs` при запущенном моке на порту 8799; подробности — `tools/uitest/README.md`.

## Сценарий демонстрации

1. Запустите `tools/mock_api.py` и откройте каталог: 8 публикаций, статусы «обработано», «частично», «в очереди», «ошибка», баннер пакетного прогона.
2. Откройте **D020**. На вкладке **Результаты** найдите `Recall`, включите **Только с замечаниями** — останутся строки с проверками.
3. Нажмите **Стр. 5** — откроется страница PDF с подсветкой; кнопка **Заголовок** подсвечивает заголовок таблицы, из которого взята единица.
4. Откройте вкладку **Замечания**, прочитайте причину и нажмите **R001** — таблица вернётся к записи с подсветкой строки.
5. Проверьте **D014** — 28 649 результатов листаются страницами по 50 без загрузки всего конверта.
6. Откройте **D013** — скан без текстового слоя: интерфейс объясняет, что OCR не выполнялся.
7. Выгрузите **CSV (область)** из шапки карточки или из каталога.

## Как устроен прототип

- `pdf_source.py` извлекает текст, строки таблиц и их ячейки. Сохраняет цитаты, страницы и прямоугольники. Для таблиц с горизонтальными линиями использует дополнительную эвристику по выравниванию столбцов.
- `rag_facts.py` распознаёт Recall, Precision, nDCG, MRR, MAP, Hit Rate, Exact Match, F1 и Accuracy. Извлекает k, переводит явно указанные проценты в доли и отмечает неизвестную шкалу для значений выше 1 без единицы. Проверяет диапазон, несовпадающие значения одной метрики и убывание Recall при росте k. Последние две проверки применяются внутри одной строки таблицы.
- `library.py` сохраняет PDF и JSON в одной транзакции SQLite. SHA-256 позволяет повторно загрузить тот же PDF без дубля.
- `server.py` обслуживает загрузку, экспорт и изображения страниц. Веб-интерфейс ищет по метрикам, значениям, контексту и цитатам в выбранной статье.
- `static/` — ES-модули нового каталога: `catalog.js`, `document.js`, `evidence.js`, `tracks/rag.js`; без сборщика и внешних зависимостей.
- `tools/mock_api.py` — заглушка API и статики для каталога: контракт `docs/adr/0008-rag-catalog-ui.md`, детерминированные фикстуры (обычная статья, скан, 28 649 строк, ошибка загрузки).

В JSON `sources` содержит фрагменты, `facts` содержит метрики и ссылается на фрагменты через `source_id`. Поле `evidence` указывает на линию текста или ячейку со значением. Поле `header` включает ячейку с названием метрики и единицей, когда они взяты из таблицы. `bbox` хранит `[left, top, right, bottom]` в PDF-пунктах от верхнего левого угла страницы, нумерация страниц начинается с 1.

## Охват текущей версии

Поддерживаются PDF с текстовым слоем до 20 МиБ и 150 страниц. Для сканов выводится предупреждение. Формулы и подписи распознаются эвристически и выдаются как цитируемые фрагменты. OCR, оцифровка кривых с графиков, многоуровневые заголовки таблиц и извлечение произвольных утверждений вне набора метрик входят в следующий этап. Проверки выявляют формальные несоответствия. Точность и полнота на корпусе организаторов ещё требуют оценки.

Методика опирается на [документацию pdfplumber по извлечению текста и таблиц](https://github.com/jsvine/pdfplumber#extracting-tables) и [BEIR как пример использования nDCG@k, Recall@k и других метрик поиска](https://arxiv.org/abs/2104.08663).
