# Гайд: Docling-адаптер PDF

`extract_document.py` умеет использовать необязательный локальный Docling-адаптер для PDF с текстом, таблицами и изображениями. По умолчанию остаётся `pdfplumber`; Docling не импортируется на этом пути. Адаптер — отдельный extraction-проход, не интеграция с backend, сайтом или UI.

## Установка

Используйте отдельное окружение Python 3.11+, чтобы не менять зависимости основного окружения:

```bash
python3.11 -m venv .venv-docling
.venv-docling/bin/python -m pip install -r requirements-docling.txt
```

Для Windows используйте `.venv-docling\Scripts\python.exe` вместо `.venv-docling/bin/python`. Файл optional-зависимостей включает базовый `requirements.txt`, `docling==2.151.1` и `docling-core==2.108.0`. Docling ставится отдельно и не добавляется в обычный список зависимостей проекта.

OCR `auto` и `full` требует установленного в системе Tesseract с языком `eng`. Python-пакет сам не устанавливает исполняемый файл Tesseract; на других машинах его и нужный языковой пакет следует установить отдельно. OCR здесь настроен только для английского.

## Запуск

Сначала выполните offline-проход без тяжёлого извлечения графиков:

```bash
.venv-docling/bin/python -m viniti extract-document data/solar/dev/D001.pdf --profile solar --mode scripts --parser docling -o data/solar/docling-D001
```

`--parser docling` включает OCR `auto` по умолчанию. Значения `--ocr auto|full|off` доступны только для Docling: `auto` включает обычный OCR-режим, `full` — полно-страничный OCR, `off` отключает OCR. Для отдельной проверки полно-страничного OCR используйте новый каталог результата:

```bash
.venv-docling/bin/python -m viniti extract-document data/solar/dev/D001.pdf --profile solar --mode scripts --parser docling --ocr full -o data/solar/docling-D001-full-ocr
```

Docling может при первом запуске скачивать веса моделей; требуется сетевой доступ. После подготовки моделей инференс выполняется локально. `--mode scripts` не использует внешний API. При `--mode auto` или `--mode model` текст по-прежнему отправляется в OpenRouter согласно настройкам CLI; изображения и результаты графиков автоматически в API не передаются. Для этих режимов по-прежнему нужны `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` либо `--model`.

### Графики — только по явному запросу

Флаг `--charts` включает локальный chart2csv VLM и требует дополнительного скачивания весов:

```bash
.venv-docling/bin/python -m viniti extract-document data/solar/dev/D001.pdf --profile solar --mode scripts --parser docling --charts -o data/solar/docling-D001-charts
```

Это тяжёлый режим: настроенная по умолчанию модель — Granite Vision 4.1 4B, ей нужны существенные загрузка и память. Не запускайте его без необходимости. Конфигурация выключает chart2code и chart2summary, `trust_remote_code=False`, а удалённые сервисы Docling отключены. Если модель требует исполнения кода из репозитория, режим завершится ошибкой, а не отключит защиту. Модельные веса имеют собственные лицензионные условия; лицензия модели не тождественна лицензии Docling.

## Выходные данные и проверка

В каталоге результата находятся `result.json`; в режиме `scripts` также `candidates.csv`. Docling-результаты парсера записываются в `parser.json`. Экспортируемые артефакты включают:

- `assets/tables/table-*.csv` — извлечённые таблицы;
- `assets/figures/figure-*.png` — crops изображений;
- `assets/charts/chart-*.csv` — извлечённые данные графиков, если запрошен `--charts` и Docling их вернул.

Таблицы и изображения помечены `requires_review`. CSV графика помечается `visual_unverified` и `requires_review`: это визуальный кандидат, а не подтверждённая метрика. Его значения нужно сверять с исходным изображением; сам факт появления CSV не устанавливает научную корректность, контекст или точность.

Docling-текст имеет статус `parser_text_only`: цифры нужно проверять по странице. BBox приводятся к началу координат `TOPLEFT`; bbox строки таблицы и её ячеек имеют область `table` и не являются точной локализацией каждой ячейки. Если элемент нельзя надёжно привязать к одной странице и bbox, он пропускается с предупреждением. Ошибка либо неполная конверсия не выдаётся за успешный частичный результат.

Ограничения адаптера: PDF до 40 МиБ и до 150 страниц; суммарный размер экспортируемых таблиц, изображений и графиков — до 32 МиБ. Данные графиков не превращаются автоматически в записи основного extraction. Полнота не измеряется; пустой или неполный результат не доказывает отсутствие сведений в документе.

Успешная установка или наличие chart API в установленной версии не подтверждают качество распознавания. Реальная конверсия D001 и одностраничная OCR-проба выполнены; подробности ниже. Научная точность на корпусе и живое восстановление чисел графиков ещё не измерены.

## Проверено 2026-11-21

- Установлены Docling 2.151.1 и core 2.108.0 в отдельном окружении Python 3.11.
- Подтверждено создание настоящего converter с chart extraction как включённым, так и выключенным; это не запуск chart VLM.
- Solar D001: полный PDF разобран с `--ocr off`, сохранены 144 текстовых/табличных источника, 2 таблицы и 8 изображений. Все ссылки на артефакты разрешаются. Пять составных текстовых элементов пропущены с предупреждениями — полнота не заявляется.
- OCR-проба: первая страница RAG D002 отрендерена в отдельный одностраничный image-only PDF в `data/solar/docling-probes/`. С `--ocr full` получены 16 источников и 4981 символ текста примерно за 14.8 секунды на подготовленном окружении. Это не прогон всей RAG D002 и не оценка точности цифр.
- Результаты: `data/solar/docling-D001-v1/` и `data/solar/docling-rag-D002-page1-v1/`. Данные, crops и веса находятся в игнорируемом `data/`, не в Git.
- Веса layout/table-моделей удалось скачать после обрывов и автоматического возобновления. Живой прогон графиков не выполнялся: native-режим требует дополнительной большой модели, а OpenRouter key/model пока не настроены.

Комплекты публикуются без перезаписи целевого каталога, в том числе при его конкурентном создании: macOS использует `renamex_np(RENAME_EXCL)`, Linux — `renameat2(RENAME_NOREPLACE)`, Windows — штатный no-replace rename. На неподдерживаемой платформе/файловой системе — явная ошибка. Race-проверки выполнены на macOS; Linux/Windows-пути локально не проверялись.

Лимит экспортируемых файлов не ограничивает пиковую RAM внутри Docling. Для обработки недоверенных загрузок в веб-сервисе потребуется отдельный worker с ресурсными ограничениями; текущий локальный CLI не является sandbox.

## Где искать реализацию

- `docling_source.py` — optional-адаптер, OCR/chart-настройки и нормализация выхода Docling.
- `extract_document.py` — CLI-параметры `--parser`, `--ocr`, `--charts`.
- `extraction_core.py` — общий конверт результата и безопасный экспорт JSON/CSV/артефактов.
- `requirements-docling.txt` — отдельные optional-зависимости.
