# Готовые решения для OCR и графиков

Исследование для текущего ML-ядра, не внедрённая интеграция. Зависимости проекта не менялись, модели не скачивались. Проверены официальные README/model card и текущие исходники Docling.

## Рекомендация

1. Сохранить pdfplumber для обычных текстовых PDF.
2. Быстрый OCR-fallback — уже установленный Tesseract.
3. Для готового комплексного разбора страниц, таблиц и изображений первым проверить Docling в отдельном окружении.
4. Для чисел с графиков проверить chart extraction Docling; при недостаточном качестве — отдельный VLM-проход по crop через OpenRouter. Качество выбранной модели измерять на наших графиках.

| Решение | Что подтверждено источником | Ограничение |
|---|---|---|
| [Tesseract](https://tesseract-ocr.github.io/) | Локальный OCR; установленная версия проверена запуском | Не восстанавливает самостоятельно научные таблицы и кривые графиков |
| [Docling](https://github.com/docling-project/docling) | OCR, layout, таблицы, изображения, структурированный JSON; macOS arm64; код MIT | Нужна проверка установки и моделей на нашем окружении; лицензии моделей отдельные |
| [Docling chart options](https://github.com/docling-project/docling/blob/main/docling/datamodel/chart_extraction_options.py) | В текущем main реализованы chart2csv, chart2summary, chart2code, VLM engines включая API | Это проверка исходников main, не подтверждение наличия функции в установленном PyPI-релизе; не гарантирует точность сложных научных кривых |
| [DePlot](https://huggingface.co/google/deplot) | Готовая модель Google «изображение графика → таблица», 0.3B, Apache-2.0 | Локальные веса/Transformers; на наших статьях не тестировалась, не универсальная оцифровка любых графиков |
| [MinerU](https://github.com/opendatalab/MinerU) | Готовый комплексный document parser; текущий README описывает CPU и Apple Silicon | Дополнительный стек, модели и измерение ресурсов; текущая лицензия Apache-based с дополнительными условиями |
| [Marker](https://github.com/datalab-to/marker) | OCR/layout/таблицы/изображения; CPU/MPS-режимы, OpenRouter-интеграция | Не равен оцифровке графиков; условия весов отличаются от Apache-2.0 кода |

Рекламные сравнительные benchmark-числа авторов не переносим на наш корпус. MinerU и Marker локально не запускались.

## Локальный OCR smoke-test

Машина: macOS arm64, 16 GiB RAM; текущий Python 3.14.3. Уже установлен Tesseract 5.5.2, языки `eng`, `osd`, `snum`; русского языка нет.

На странице 1 `rag-participant-kit/dev/D002.pdf`:

- исходный текстовый слой: 0 символов;
- рендер 180 DPI и `tesseract ... -l eng --psm 3 tsv`;
- получено 697 слов с координатами;
- полное время одного запуска: примерно 2.59 секунды.

Это только проверка работоспособности на одной странице, не benchmark корпуса. OCR confidence не является оценкой научной точности; сравнение с gold не выполнялось.

## Графики: особая модель доказательств

Извлечь картинку из PDF и восстановить её числовые данные — разные задачи. Chart2table/VLM может перепутать серии, логарифмическую ось, error bars и мелкие подписи.

Сохранять: страницу, bbox crop, изображение, подпись, названия осей/единицы, серию, исходный ответ модели, метод и статус `requires_review`. Оценки по кривой помечать как приблизительные. Не объявлять их `literal_verified`: проверка текстовой цитаты не подтверждает значение, считанное по изображению.

При интеграции отключить chart2code: нам нужны данные, а не исполняемый код от модели. Не исполнять сгенерированный код.

Отдельно проверить на небольшой dev-выборке: столбцы, несколько кривых, логарифмическая ось, многопанельный график. Без этих проверок не обещать автоматическую поддержку любых графиков.

## API

Публичный каталог [OpenRouter models](https://openrouter.ai/api/v1/models) на момент проверки содержит бесплатные варианты с image input и поддержкой structured output. Нулевая указанная цена не означает отсутствие rate limits или гарантированную доступность. Live-inference не выполнялся.

Передавать внешнему провайдеру только разрешённые материалы; API-ключ не помещать в результаты, Git или чат.
