## Реальные баги

### 🟡 B-01. «Фрагменты PDF» молча обрезает выдачу: 411 → 200

- **Где:** `static/document.js:718` — запрос `{limit: 200}`, пагинатора нет; счётчик показывает `data.total` (строка 720).
- **Шаги:**
  1. Открыть `http://127.0.0.1:8799/#/doc/rag%3Ad020?track=rag&tab=sources`.
  2. Посмотреть счётчик и число строк.
  3. Для API: `curl -s 'http://127.0.0.1:8799/api/documents/rag%3Ad020/sources?limit=200'`.
- **Ожидалось:** доступны все 411 фрагментов (пагинация/«показать ещё») **или** явно написано «показано 200 из 411».
- **Фактически:** счётчик «Фрагментов: 411», в таблице 200 строк; пагинатора/пометки об обрезке нет. API отдаёт `total=411, items=200`. Аналогичный жёсткий `limit: 200` есть у вкладки «Замечания» (`document.js:649`); на текущих фикстурах замечаний 3, но на большом документе они также могут исчезнуть без следа.
- **Вьюпорт:** 1366×900. **Приоритет:** P2 (искажение данных, не блокер демо).
- **Проверка:** `node passport.mjs` это не покрывает; воспроизводится вручную/`curl`; в отчёте `2026-11-20-rag-catalog.md` было D1 и осталось.

### 🟡 B-02. Прямая ссылка на результат вне первой страницы не открывает и не подсвечивает запись

- **Где:** `static/document.js:368` (читается `params.result`), но в запрос `/results` (строки 466–470) `result` не передаётся; страница остаётся первой.
- **Шаги:**
  1. Открыть `http://127.0.0.1:8799/#/doc/rag%3Ad020?track=rag&result=R060`.
  2. Сравнить с `...&result=R060&page=2`.
- **Ожидалось:** запись найдена, страница вычислена/открыта, строка подсвечена и раскрыта.
- **Фактически:** `?result=R060` показывает «страница 1 из 9», `tr.target` = 0. С `&page=2` — 1 target и раскрытые детали. Ссылки из «Замечаний» формируются без `page`, поэтому замечание к записи дальше 50-й не подсветится. На текущих фикстурах все `record_ids` (R001/R002/R007) на первой странице, поэтому в демо дефект не виден.
- **Вьюпорт:** 1366×900. **Приоритет:** P2 (прямые ссылки/большие документы).
- **Проверка:** собственный `current-check.mjs`; в `passport.mjs` не входит.

### 🟡 B-03. На 390 px паспортная таблица всё ещё скроллится горизонтально

- **Где:** `static/style.css:244` — `.results table { min-width: 720px; }`; мобильное правило `table { min-width: 0; }` (`style.css:414`) имеет меньшую специфичность и не перебивает его. Паспорт теперь использует `.results` (`passport.js:388`), поэтому таблица остаётся 720 px.
- **Шаги:**
  1. Открыть `#/passport` на 390×844.
  2. Импортировать любой паспорт (например, общий формат с одной строкой).
  3. Измерить `#view .workspace .results`.
- **Ожидалось:** по новому дизайну колонки сжимаются, внутреннего горизонтального скролла нет.
- **Фактически:** `scrollWidth = 720`, `clientWidth = 322`, `overflow-x: auto`; пользователь скроллит таблицу вбок. Страница при этом не переполняется (390), каталог тоже скроллится внутри — как и ожидалось.
- **Вьюпорт:** 390×844, Chromium 159. **Приоритет:** P2 (мобильный сценарий; не блокер desktop-демо).
- **Проверка:** единственное падение `node passport.mjs` — «мобилка: паспортная таблица не скроллится внутри». Если продуктовое решение — оставить скролл, проверку нужно инвертировать; сейчас она фиксирует заявленное поведение.

### ⚪ B-04. Старый диалог доказательства остаётся при переходе на битый `source_id`

- **Где:** `static/app.js:111` закрывает диалог только когда в маршруте нет `/source/`; `static/evidence.js` в `openEvidence()` не закрывает его при ошибке якоря.
- **Шаги:**
  1. Открыть `#/doc/rag%3Ad020/source/1001?track=rag` — диалог с цитатой R001.
  2. В адресной строке заменить `1001` на `999999`, не закрывая диалог.
- **Ожидалось:** старая модалка закрывается или показывает ошибку; пользователь не видит чужую цитату.
- **Фактически:** диалог остаётся открытым с прежней цитатой `BM25 | Table 3 | Recall | 0.81` и заголовком «Источник · страница 5», хотя URL уже `/source/999999`, а `#status` пишет «Не удалось открыть источник: Источник не найден.».
- **Вьюпорт:** 1366×900. **Приоритет:** P3 (редкий stale-state, но легко воспроизводится).

### ⚪ B-05. `facts` с `unit: "unspecified"` теряют значение в таблице и заголовке карточки

- **Где:** `static/passport.js:74-77` — для `facts` значение подставляется в `normalized_value` только если `unit !== "unspecified"`; `value()` (`:147-150`) читает только `normalized_*`/`raw_*`.
- **Шаги:** открыть `#/passport`, импортировать:
  ```json
  {"title":"RAG","facts":[{"id":"F1","metric":"Recall","value":81,"unit":"unspecified",
    "raw_value":"81%","evidence":{"page":5,"quote":"Recall 81%"}}]}
  ```
- **Ожидалось:** значение видно (`81` или `81%` с пометкой «единица не указана») в таблице и карточке.
- **Фактически:** таблица `Recall —`, заголовок карточки `Recall`; в деталях «Исходное значение 81%» и цитата есть. `rag_facts.py` выдаёт `unit: "unspecified"` для значений > 1 без единицы, поэтому это не только синтетика.
- **Вьюпорт:** 1366×900. **Приоритет:** P3 (данные не потеряны полностью, но главное значение скрыто).

### ⚪ B-06. `#/doc/foo` показывает «Раздел foo не подключён» вместо «Документ не найден»

- **Где:** `static/app.js:117-128` — для любого `docId` без `:` выбирается `desired = docId.split(":")[0]`, ищется дескриптор и выводится сообщение об области.
- **Шаги:** открыть `http://127.0.0.1:8799/#/doc/foo?track=rag`.
- **Ожидалось:** сообщение о несуществующем документе и ссылка в каталог (как для `rag:nope`).
- **Фактически:** «Раздел «foo» пока не подключён…», кнопки загрузки/демо disabled, к каталогу ведёт только ссылка «Перейти в каталог RAG».
- **Вьюпорт:** 1366×900. **Приоритет:** P3 (некорректный адрес; на демо не критично).

### ⚪ B-07. CSV: защита от формул больше не покрывает ведущие пробелы/переводы строк

- **Где:** `static/passport.js:152-155` — регулярка `^[=+\-@\t\r]`; прежняя версия использовала `^[\s]*[=+\-@]`.
- **Шаги:** импортировать `{"title":"T","results":[{"id":"C1","metric":" =1+1","value":1,"unit":"u","validation_status":"passed","extraction_status":"extracted"}]}` и скачать CSV.
- **Ожидалось:** ячейка с ведущим пробелом перед `=` экранируется апострофом (как раньше), либо это осознанно задокументировано.
- **Фактически:** в CSV `" =1+1"` без апострофа; `=cmd` без пробела по-прежнему экранируется. Риск низкий (Excel обычно не считает формулой строку с ведущим пробелом), но защита сузилась.
- **Вьюпорт:** 1366×900. **Приоритет:** P3 (безопасность/регрессия узкой проверки).

## Вопросы (нужно продуктовое решение, не баг)

1. **Явный `validation_status: "passed"` без извлечения.** Сейчас `validation()` (`passport.js:125-130`) возвращает «Пройдена» для явного passed даже при `extraction_status: "present_not_extractable"`, и такая строка попадает в CSV с пустыми `metric_value`/`normalized_value`. Старое правило требовало `passed` **и** `extracted`. Нужно решить: доверять явному статусу или исключать не извлечённые строки. Воспроизведение: импорт `{"results":[{"id":"P1","metric":"NoExtract","value":0.5,"unit":"u","validation_status":"passed","extraction_status":"present_not_extractable"}]}` → «Прошли проверку 1», CSV активен, строка с пустыми значениями.
2. **Solar без одной из семи таблиц.** `passportRows()` (`passport.js:42-56`) при неполном наборе молча уходит в общий формат `results`: строки и значения показываются, но `context`, «Прибор», «Материал», «Слои» теряются, ошибки нет. Ожидалось бы явное «нужны семь таблиц» или предупреждение. Воспроизведение: взять `solar-tables.json` и удалить `issues`.
3. **Заголовок Solar-паспорта.** Для семи таблиц название статьи лежит в `publications[0].title`, но `.lede` показывает «Паспорт статьи», `.eyebrow.data` — «Импортированный паспорт» (`passport.js:100-105`). Для общего формата/`facts` название в `.lede` работает. Стоит подставлять публикацию Solar в `.lede`/тему.
4. **`unit: "unspecified"`** — показывать `raw_value` в таблице/заголовке или оставить «—» как осознанный отказ от нормализации? Сейчас значение видно только в деталях (см. B-05).
5. **CSV и фильтры.** После правок CSV не зависит от выбранной строки/фильтра и выгружает **все** passed-строки. Это соответствует «CSV только из прошедших проверку», но подпись рядом с фильтрами может намекать на «выгрузить видимое». Если нужно второе — добавить пояснение/вариант.
6. **Мок: баннер «Обработано 4 из 90» при 8 документах в каталоге.** Это фикстура `/api/jobs` (total 90), не UI-баг; но на демо цифры выглядят противоречиво.

## Изменилось по решению (не считать регрессиями)

Проверено в текущей версии; это новые договорённости, а не баги:

- H1 на `#/passport` всегда «Паспорт публикации.»; название статьи — в `.lede`, тема/набор — в `.panel-head .eyebrow.data`.
- CSV переехал в `.panel-head` панели «Результаты» и стал `secondary`; в герое только «Импорт паспорта JSON» (`primary`) и «Привязать исходный PDF».
- На `#/passport` скрыты `#upload` и `#tracks`; у ссылки «Паспорт» `aria-current="page"`. Каталог и карточка возвращают контролы.
- Обратная связь импорта inline: `.notice.good` («Паспорт загружен. Записей: N…») или `.notice.bad[role="alert"]`; `#status` для импорта не используется. Битый JSON локализован («Файл не является корректным JSON.»), предыдущие данные сохраняются.
- Вывод статуса без `validation_status`: замечания → «На разборе»; `extraction_status: extracted` без замечаний → «Пройдена» (tooltip у бейджа + notice «статус «Пройдена» выведен…»); иначе «Ожидает». На реальном Solar `dev_gold` (659 строк) это даёт 595 passed / 58 review / 6 pending, CSV доступен.
- Общий формат `results` маппит `value`/`unit` → `normalized_value`/`normalized_unit`; вложенный `entry.source`/`evidence.page` читается, поэтому собственный `export.json` показывает страницу/цитату и даёт PDF-ссылку.
- CSV: BOM, кавычки/CRLF/`fields`, защита `= + - @ \t \r`; CSV не гаснет при пустом фильтре, если passed-строки есть.
- Вкладка «Сводка» больше не дублирует карточки «Результатов/Замечаний/Обработки» (осталась `.stats` в шапке).

## Продуктовые решения по вопросам отчёта

1. **Явный `validation_status: "passed"` без извлечения.** Статус в интерфейсе остаётся «Пройдена» (явный статус бэкенда главнее), но в CSV попадают только строки со статусом «Пройдена» **и** извлечённым значением: `present_not_extractable`/`absent` и пустые значения исключаются. У кнопки CSV появилась подсказка «Строки со статусом «Пройдена» и извлечённым значением». Так счётчик «Прошли проверку» и число строк CSV могут расходиться — это осознанно.
2. **Solar без одной из семи таблиц.** Набор распознаётся по наличию `publications` и `results`; недостающие таблицы подставляются пустыми, поэтому контекст прибора/материала/слоёв из доступных таблиц сохраняется. Над таблицей выводится предупреждение: «Набор Solar неполный: нет таблиц …».
3. **Заголовок Solar-паспорта.** Название статьи берётся из `publications[0].title`: оно показывается в `.lede`, а публикация — в `.eyebrow.data`.

## Правки по код-ревью 2026-11-21

- `locateResult()` больше не дописывает статус устаревшего поиска: после `await` проверяются `id !== request` и `signal.aborted`, целевой `result_id` фиксируется до скана, сетевой сбой отличается от «не найдено».
- Выбранная строка паспорта сбрасывается, если после смены фильтра или окна оказалась вне видимых строк; фокус после «Показать ещё» переходит на первую новую строку.
- Вкладка «Замечания» больше не режет список молча: при `items.length < total` счётчик пишет «показаны первые N».
- После ошибки якоря URL очищается от `/source/<id>`.
- `?track=` для документа без префикса области нормализуется, а неизвестная область в каталоге по-прежнему даёт явную ошибку.
- `normalized_unit: "unspecified"` больше не показывается как единица.
- Счётчик окна паспорта: «Показано 200 из 403 · всего 408 · ещё 203» — без противоречия между знаменателем и остатком.
