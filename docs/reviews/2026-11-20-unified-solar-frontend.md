# Ревью: единый фронтенд в визуальном языке `dev`

- **Дата:** 2026-11-20
- **Ветка:** `feature/rag-frontend`
- **Объект ревью:** `4c7b90c` «feat(ui): unify frontend in the dev solar visual language», diff `3e9de61..4c7b90c`
- **Файлы:** `static/style.css` (переписан), `static/index.html`, `static/app.js`, `static/catalog.js`, `static/document.js`, новый `static/passport.js`; удалены `static/solar.html`, `static/solar.css`, `static/solar-ui.mjs`; `server.py`, `tools/mock_api.py`; `README.md`, `docs/adr/0009`, новый `docs/adr/0010`

## Вердикт

**Нужны правки. Блокеров нет, но паспорт нельзя объявлять готовой фичей.**

Каталог и карточка не регрессировали: харнесс `43/43`, e2e `15/15`, `unittest 2/2`, старые
селекторы и адреса на месте, XSS нет. Визуальная унификация сама по себе мержабельна.

Паспорт — нет: `validation()`/CSV не работают на двух из трёх заявленных форматов импорта
(`results` и `facts`), при импорте собственного `/export.json` этого приложения теряются
страница и цитата источника, а тестов на новый модуль нет ни одного. Это три пункта, которые
я бы закрыл до мержа (B1–B3 ниже), плюс решение по `server.py` (B4); остальное — можно
отдельной задачей. Оговорка честности: B1/B2 и часть ⚪ переехали из `solar-ui.mjs` как есть, то есть это **не регрессия** этого
коммита, а унаследованный долг — но теперь он опубликован в основном приложении и обещан в
README, поэтому «как было в dev» перестаёт быть оправданием.

## 🟡 Важно

### B1. CSV и «Прошли проверку» не работают для `results`/`facts` без `validation_status`

- **Где:** `static/passport.js:110-114` (`validation`), `static/passport.js:291-296`
  (`syncActions`), `static/passport.js:132-145` (`download`); README:43.
- **Что не так:** статус вычисляется только из `row.result.validation_status`
  (`review`/`passed` + `extraction_status`). Ни экспорт каталога (`results`), ни `facts` из
  `rag_facts.py`, ни таблицы Solar поля `validation_status` не содержат. Проверено на живом моке:
  - импорт `/api/documents/rag:d020/export.json` → сводка **408 / 0 / 3**, кнопка «Скачать CSV»
    `disabled`, и остаётся такой всегда;
  - синтетический `facts` (формат `analyze()`) → **2 / 0 / 1**, CSV `disabled`;
  - синтетический Solar (7 таблиц) → **2 / 0 / 1**, CSV `disabled`.

  Работает только формат dev-паспорта, где `validation_status` проставлен явно. README при этом
  перечисляет `results` и `facts` как поддерживаемые, а «Скачать CSV» — как центральную функцию
  паспорта.
- **Почему важно:** пользователь открывает единственный естественный файл этого приложения
  (`/export.json`), видит «Прошли проверку: 0» и мёртвую кнопку. Никакой ошибки, просто тихо
  не работает.
- **Предлагаю:** нормализовать статус при разборе (`passportRows`, `static/passport.js:58-84`):
  если `validation_status` отсутствует, считать `passed` при `extraction_status === "extracted"`
  и пустых `issues`, иначе `review`/`pending`. Как минимум — описать ограничение в README и
  тултипом у кнопки, чтобы это не выглядело багом.

### B2. Импорт собственного `/export.json` теряет страницу и цитату источника

- **Где:** `static/passport.js:69-70` (`source_page: entry.source_page ?? entry.evidence?.page`),
  `static/passport.js:77-80` (сборка `source`), `static/passport.js:228-239` (показ/ссылка на PDF).
- **Что не так:** у результатов `export.json` источник лежит во вложенном объекте
  `entry.source = {page, section, table, figure, fragment}`. Маппинг читает только плоские
  `source_page`/`source_fragment` (dev-формат) и `entry.evidence` (`facts`). Проверено: после
  импорта 408 строк карточка результата не показывает ни «стр. 5», ни цитату, хотя они есть в
  файле. Привязка PDF при этом рапортует «PDF привязан к публикации D020.», но ссылка «Открыть
  страницу PDF» не появляется никогда (`evidence.page` пуст) — пользователь видит подтверждение
  действия и ничего больше.
- **Почему важно:** «доказательства из статьи» — второе название экрана; для файла, который это
  же приложение выгружает, доказательств нет.
- **Предлагаю:** добавить в маппинг `entry.source?.page`, `entry.source?.fragment`,
  `entry.source?.section/table/figure`. Это одна строка на поле и чинит оба симптома сразу.

### B3. У паспорта нет ни одной автоматической проверки

- **Где:** `tools/uitest/harness.mjs` (43 проверки, все про каталог/карточку),
  `tools/uitest/e2e.mjs` (15 проверок, там же); новый `static/passport.js` (365 строк);
  `.github/workflows/smoke.yml` гоняет только `python -m unittest`.
- **Что не так:** ни импорт JSON, ни `validation()`/CSV, ни экранирование CSV, ни отзыв
  object URL, ни `#/passport`-маршрут не покрыты. Регрессии в паспорте не поймает ничего.
- **Почему важно:** именно в этом модуле сосредоточена вся новая логика коммита, и часть её
  (B1/B2) уже расходится с документацией.
- **Предлагаю:** минимальный jsdom-блок в `harness.mjs` — демо (`2/1/1`), импорт фикстуры с
  `validation_status` (CSV `enabled`, содержимое первых строк, `=HYPERLINK` начинается с `'`),
  импорт битого/пустого JSON (старый экран не рушится), `#/passport` в адресе. 6–8 проверок
  закрывают все находки этого отчёта.

### B4. `server.py` окончательно перестал отдавать хоть один рабочий экран

- **Где:** `server.py:18-22` (после удаления `/solar*` в `ASSETS` остались `/`, `/style.css`,
  `/app.js`), README:16 (первая команда запуска — `.venv/bin/python server.py`).
- **Что не так:** до коммита `/solar` под `server.py` был единственным экраном, который работал
  без мока (статические файлы паспорта не требовали API). Теперь `/` отдаёт `index.html`, чей
  модульный граф падает на первом `import` (`/dom.js`, `/passport.js`, `/solar.mjs` → 404), а
  `/solar*` удалены. Проверено: `server.py` → `/` 200, `/app.js` 200, всё остальное 404; через 4 с
  появляется `bootError` с просьбой запустить мок.
- **Почему важно:** README начинается с `server.py`, и этот путь теперь ведёт только к экрану
  ошибки (раньше можно было показать хотя бы паспорт). ADR-0010 фиксирует долг «раздача статики —
  Мите», но факт «мы убрали единственный работавший экран» в нём не отражён.
- **Предлагаю:** либо 5 строк generic-обработчика `static/**` в `server.py` (типы — через
  `mimetypes` из stdlib), либо явно в README: «оба экрана открываются только через
  `tools/mock_api.py`; `server.py` обслуживает прежний API и UI не показывает».

### B5. CSV без BOM и неполный набор формула-инъекций

- **Где:** `static/passport.js:126-130` (`csvCell`), `static/passport.js:139` (`new Blob`).
- **Что не так:**
  1. CSV отдаётся как UTF-8 **без BOM**. Значения и цитаты здесь кириллические; Excel на Windows
     (а Windows в README поддерживается) откроет такой файл в системной кодировке и покажет
     кракозябры. Проверено содержимое выгрузки — BOM нет.
  2. `csvCell` префиксирует `'` только для `= + - @` после пробелов. OWASP относит к опасным
     также **ведущие `\t` и `\r`**: ячейка `"\t=1+1"` покрыта, а `"\tтекст"` — нет. Само по себе
     безобидно, но проверка обещает больше, чем делает.
- **Предлагаю:** `new Blob(["\uFEFF" + ...])`; в регексе проверять `^[\s]*[=+\-@\t\r]` (или
  префиксовать любой текст, начинающийся с `\t`/`\r`). Экранирование кавычек, CRLF и `-5`
  (число остаётся числом) уже сделано верно — это проверено.

### B6. Карточка результата обновляется без объявления для скринридера

- **Где:** `static/passport.js:157` (`<div id="detail">`), `static/passport.js:274-283`
  (клик по строке), `static/index.html:20` (ссылка «Паспорт»).
- **Что не так:** выбор строки — это `button` с `aria-pressed`, а правая панель меняется молча:
  нет ни `aria-live`, ни `aria-controls`/связи с кнопкой, ни переноса фокуса. Пользователь
  скринридера нажимает «Recall» и не узнаёт, что справа появились значение, статус, цитата.
  Дополнительно ссылка «Паспорт» в тулбаре никак не помечает текущий раздел (`aria-current` нет,
  в отличие от кнопок областей с `aria-pressed`).
- **Предлагаю:** `aria-live="polite"` на `#detail` (или на контейнере карточки) либо
  `aria-controls="detail"` у кнопки строки; `aria-current="page"` для «Паспорт» на `#/passport`.

## ⚪ Мелочи

1. **Мёртвые селекторы после удаления solar-файлов:** `static/style.css:45` и `:394` — `.shell`
   (в `index.html` больше нет), `:160` и `:399` — `.doc-title` (нигде не ставится, `document.js`
   использует `h1` в `.doc-hero`), `:342` — `.notice.good`. Класс `nav-link`
   (`static/index.html:20`) в CSS не описан — безвредно, но выглядит как забытый хук. Удалить
   или начать использовать.
2. **`filterSolarCatalog` не используется** (`static/solar.mjs:59-83`): паспорт фильтрует строки
   своими ~10 строками (`passport.js:248-259`), потому что у него другая семантика статуса.
   Дублирование логики фильтра — кандидат на унификацию, но сейчас это мёртвый экспорт
   (он был мёртв и до коммита).
3. **CSV отключается по выделению, хотя выгрузка от него не зависит** (`passport.js:292`):
   `download(rows, …)` берёт **все** строки и сам отбирает прошедшие, а `syncActions` гасит
   кнопку при `!selected`. Проверено: достаточно отфильтровать таблицу в «ничего не найдено» —
   CSV становится недоступен, хотя данные для экспорта есть. В dev кнопка от выделения не
   зависела — это новое расхождение. И наоборот: CSV не учитывает активные фильтры, хотя
   подпись «Скачать CSV» рядом с фильтрами намекает на обратное. Решить одно из двух и
   подписать.
4. **Формат ошибки импорта** (`app.js:211`): в статус уходит сырое сообщение движка —
   «Не удалось загрузить паспорт: Expected property name or '}' in JSON at position 1 (line 1
   column 2)». Пользователю нужнее «Файл не является корректным JSON» + имя файла.
5. **Ошибка в `#status` переживает смену экрана.** Проверено: после неудачного импорта уходим
   в `#/` и возвращаемся — «Не удалось загрузить паспорт…» всё ещё висит. Поведение общее для
   роутера (было и раньше), но с импортом стало заметнее. Чистится одной строкой в `route()`.
6. **Нет фидбэка об успешном импорте.** В dev после импорта было «Паспорт загружен. CSV включает
   только прошедшие проверку записи», сейчас `say("")` просто чистит статус. Исчезновение
   демо-плашки — единственный сигнал. Для файла на 28k строк без индикатора это неудобно:
   импорт занимает ~2 с, поиск по 28 649 строкам — ~1 с на каждое нажатие клавиши (замерено),
   дебаунса нет (в `catalog.js`/`document.js` он 250 мс).
7. **Валидный, но пустой паспорт** (`{"results": []}`) показывает «Результаты не найдены» и
   «Выберите результат в таблице» — как будто фильтр не дал совпадений. Лучше отдельное
   «В паспорте нет результатов».
8. **Точка после произвольного заголовка** (`passport.js:312`): `title + "."` даёт `…RAG.` для
   нормального заголовка, но `…?` + `.` → «….» для заголовка с вопросительным знаком. Мелочь

9. **Object URL привязанных PDF не освобождаются при уходе с `#/passport`** — отзыв только в
   `setPassport` (`passport.js:99`). Утечка маленькая и до перезагрузки, но если у экрана

10. **Ключ привязки PDF — только `publication_id`** (`passport.js:186`), фолбэк `"article"`
    (`passport.js:59`) общий для всех строк без id: PDF «прилипнет» ко всем сразу.
11. **Дублирование сводки в карточке документа:** новая `.stats` (`document.js:63-67`) и старые

12. **Дублирование controls:** «Импорт паспорта JSON» есть и в тулбаре (`index.html:27-29`), и в

13. **«Демо» на экране паспорта** открывает RAG-демо-статью, а не демо-паспорт, хотя паспорт уже

14. **`#passport` «заперт» на неизвестной области:** `#/passport?track=solar` рендерит «Раздел

## Проверено и претензий нет

- **XSS.** Проба с `<img src=x onerror=alert(1)>` в `title`, `<script>`/`<svg onload>` в
  значении и цитате: ни одного срабатывания, ноль созданных `img`/`svg` в `#view`. В `static/`
  нет `innerHTML`/`insertAdjacentHTML`/`eval`; все данные идут через `el(..., {text})` →
  `textContent`. `href` собирается только из `blob:`-URL и `page`, проверенного регуляркой
  `/^\d+$/` (`passport.js:234`).
- **CSV-экранирование.** Кавычки удваиваются, строки через CRLF, `=HYPERLINK("http://evil")`
  получает `'`, `-5` остаётся числом, `fields` сериализуется в JSON-ячейку, шапка фиксированная
  (инъекция через заголовки невозможна). B5 — про BOM и хвост набора символов, а не про
  экранирование.
- **Повторный импорт.** Object URL старых PDF отзываются (`passport.js:99-100`): после
  переимпорта ссылка «Открыть страницу PDF» исчезает, `pdfInput` снова активен. Битый JSON и
  объект с `results: {}` **не затирают** предыдущий экран: `passportRows` валидирует до отзыва
  URL и присваивания `current` (`passport.js:96-108`) — проверено, строки и заголовок остались.
- **Данные не уходят на сервер.** Во время импорта ноль запросов к `/api/*` (перехват в
  Chromium) — обещание README выполняется.
- **Привязка PDF (для формата с `source_page`).** Синтетический паспорт с `source_page: 7` +
  локальный PDF → ссылка появляется, `href` начинается с `blob:http://` и содержит `#page=7`,
  `target=_blank`, `rel=noopener`.
- **Фильтры паспорта.** Метрика/проверка/поиск работают; при выпадении выбранной строки
  выделение переходит на первую подходящую (`passport.js:260`), при пустом результате карточка
  показывает «Выберите результат в таблице», счётчик (`aria-live="polite"`) — «Результаты не
  найдены». Метрики пересобираются при каждом рендере, дублей нет.
- **Маршрут `#/passport`.** Работает прямым адресом, с `?track=rag`, через ссылку «Паспорт»;
  возврат на `#/` рендерит каталог, повторный заход на паспорт сохраняет импортированные данные;
  `document.title` ставится на каждом экране; `#/passport/` → «Страница не найдена» (как и
  прочие неизвестные пути).
- **Дубли id.** На экране паспорта ровно один `#passport` (в тулбаре) и один `#detail`; с
  `detail-<id>` из `document.js` не пересекаются, потому что вьюхи не сосуществуют. Проверено
  `querySelectorAll("[id]")` — дублей нет.
- **Доступность в целом.** Файловые input’ы обёрнуты в `label` и не спрятаны через `display:none`
  (`.file:focus-within` даёт кольцо), у поиска/селектов `aria-label`, у таблицы `<caption
  class="sr-only">` и `th scope="col"`, статусы передаются текстом, а не цветом, у кнопок строк
  `aria-pressed`, у счётчика `aria-live`, skip-link и `:focus-visible` на месте, `#view` без
  паразитной обводки.
- **CSS.** Конфликта `.status` больше нет: строка состояния осталась единственным носителем
  класса (`#status.status`, `app.js:55-58`), бейджи ушли в `.badge.ok/warn/bad/idle`. Классы,
  удалённые из CSS вместе со старой оболочкой (`screen`, `screen-head`, `doc-head`, `crumb`,
  `topbar`), в JS/HTML больше не встречаются. Остальные селекторы используются (проверено
  скриптом по классам). Медиазапросы 880/760 px работают: `#/`, `#/doc/...`, `#/passport` (в т.ч.
  после импорта) на 390 px без горизонтального скролла. Липкая шапка таблиц работает в
  `.results` (`overflow:auto` + ограничение высоты), как и раньше.
- **Регрессии каталога и карточки.** Харнесс подтвердил: `#/`, `#/doc/rag:d020?track=rag`,
  поиск, статусы, баннер прогона, `tab=`/устаревший `view=`, пагинация и её зажим, `?result=`
  с подсветкой/раскрытием/фокусом, «только с замечаниями», пустое состояние со сбросом,
  вкладки (стрелки/Home/End), сущности, фрагменты, скан без OCR, диалог доказательств,
  глубокие ссылки `/source/`, неизвестная область, 404 документа. e2e добил сортировку,
  XSS-строку в поиске, загрузку PDF, Esc в диалоге. Структура фильтров, `limit/offset`,
  `patch/go` и `q/metric/k/dataset/config/status/issues/result/page` не менялись;
  `.doc-main h1`, `.doc-actions`, `.tabs`, `.count`, `.pager`, `tr.result/detail/target`
  сохранены — тесты на них держатся и проходят.
- **Сводка/герой карточки.** `.stats` и `.hero doc-hero` рендерятся для всех статусов, `h1`
  остаётся `.doc-main h1`, `.doc-hero` перебивает крупный кегль `.hero h1` (одинаковая
  специфичность, правило ниже) — визуально корректно.
- **`server.py`/`mock_api.py`.** Алиас `/solar` убран, `/solar*` → 404, `passport.js` и
  `solar.mjs` отдаются с `text/javascript`; path traversal в моке не появился
  (`STATIC.resolve() not in target.parents`). `unittest` не затронут — 2/2.

## Что осталось непроверенным

- **Реальные данные Solar и dev-паспорта** (не синтетика): есть ли в таблице `results`
  `validation_status` и как выглядит настоящий `facts`/паспорт. От этого зависит, насколько
  B1 практическая, а не теоретическая: если реальные файлы всегда приходят с
  `validation_status`, B1 — про документацию, а не про код.
- **Кросс-браузерность ссылки на PDF:** `blob:…/#page=N` проверена только в Chromium.
  Поведение Firefox/Safari для фрагмента на blob-URL не гарантировано (наследие dev).
- **Скринридеры:** вручную не слушал, выводы про доступность — по разметке и клавиатуре.
- **Полная визуальная сверка с `origin/dev`:** сверял токены и скриншоты, а не попиксельно
  (в ADR-0010 это заявлено как риск).
- **`server.py` как продуктовый путь:** только факт 404 по модулям; живую загрузку/экспорт через
  него не гонял (это было в ревью ADR-0008 и не менялось).
- Поведение фокуса после стрелок на вкладках — работает (`tab-entities` получает фокус), но
  зависит от гонки `requestAnimationFrame` и `focusView()`; код этих путей этим коммитом не
  менялся, поэтому в находки не выношу.

## Итог

Правка делает ровно то, что заявлено: один документ, один `style.css`, один роутер, визуал
`dev` на всех трёх экранах, каталог и карточка без потерь. Перенос паспорта аккуратный по коду
(никакого `innerHTML`, корректный отзыв URL, безопасный CSV), но по продукту он недоделан:
B1–B3 стоит закрыть в этом же PR — это два небольших маппинга и один блок тестов. B4 — решить,
что делать с `server.py` (5 строк кода или строчка в README). Остальное можно вынести в
отдельную задачу «паспорт: полировка и доступность».
