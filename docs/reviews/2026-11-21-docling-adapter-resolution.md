## Проверка `atomic_output.py`

- `atomic_output.py:15–23`: macOS вызывает `renamex_np` с `RENAME_EXCL = 0x4`; Linux — `renameat2(AT_FDCWD, ..., AT_FDCWD, ..., RENAME_NOREPLACE)` с `AT_FDCWD = -100` и флагом `1`. ABI аргументов задан явно; пути кодируются через `os.fsencode`.
- `use_errno=True`, `restype=c_int` и немедленный `ctypes.get_errno()` корректно сохраняют errno неуспешного вызова. Ошибка превращается в `OSError`, который существующий CLI умеет обрабатывать.
- Windows использует `Path.rename`: существующий target не заменяется. Отсутствующий символ libc / неизвестная платформа приводят к безопасному `ENOSYS`, без небезопасного fallback на обычный POSIX rename. Неподдерживаемый kernel/filesystem также возвращает ошибку, а не ослабляет гарантию.
- В `extraction_core.py:387–433`, `solar_facts.py:405–416`, `solar_extract.py:163–171` staging создаётся в родителе output: обычный случай остаётся в одной файловой системе. При отказе публикации `TemporaryDirectory` удаляет staging, но не чужой target.
- Проверка `output.exists()` остаётся ранней диагностикой, а не механизмом защиты от гонки. Защита теперь находится в системной операции.
- Блокирующих проблем helper не найдено. Гарантия — атомарная видимость и отсутствие замены target, **не** durability при потере питания и не защита от атакующего, способного подменять родительские каталоги.

## Что хорошо

- Исправления локальны, default parser не меняется; закрытие race распространено на все три экспорта, а не только Docling.
- `docling_source.py:64` явно принудительно задаёт `trust_remote_code=False`; `chart2code`/`chart2summary` отключены. Это не ослаблено ради работоспособности модели.
- Numeric chart filter не выдаёт научную верификацию: `visual_unverified/requires_review` сохраняются.
- QA-тест race теперь проверяет настоящую no-replace операцию после создания target, а не мок обычного `Path.rename`.

## Проверки и оставшиеся ограничения

- Это **статическое** повторное ревью. Попытка запуска `python -m unittest test_docling_source test_docling_qa -q` в optional Python 3.11 env отклонена разрешениями shell. Новых успешных тестовых прогонов от имени reviewer не заявляю.
- macOS SDK constant проверен developer, согласно задаче; Linux/Windows ветки здесь не исполнялись. Для переносимости полезны отдельные проверки helper: успешная публикация, существующий пустой target, файл/симлинк-target, отсутствие символа и сохранение source при отказе.
- Успешный реальный D001 conversion, наличие таблиц/фигур и успешное создание converter с `charts=True/False` сообщены developer. Это не независимая проверка качества OCR/chart inference. OCR probe не дублировался; научная точность не измерена.
- Ограничения памяти из первоначального ревью сохраняются: byte/page budgets не ограничивают пиковую RAM при рендере, конверсии и PNG-кодировании. Полнота извлечения остаётся `partial/not_measured`.
- Старые воспроизведения в отчёте от 2026-11-20 описывают состояние **до** исправлений и больше не являются ожидаемым поведением текущего кода.
