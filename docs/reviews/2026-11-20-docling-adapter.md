## Находки

- 🟡 `docling_source.py:192–207` — пустой `chart_data` считается полученным графиком. `table_grid({"num_rows": 0, "num_cols": 0, "table_cells": []})` допустим, после чего создаются пустой CSV и `visual_candidates`, а предупреждение «числовые данные графиков не получены» подавляется. Это смешивает отсутствие результата с кандидатом на проверку. Предложение: пустую/полностью пустую сетку не добавлять в кандидаты, выдавать предупреждение с `figure_id`; отдельно отмечать отсутствие числовых значений, не пытаясь автоматически подтверждать их научный смысл.
- 🟡 `extraction_core.py:329–330` — для Docling в режимах `auto/model` остаётся причина покрытия «Только текстовый слой; OCR/графики не обработаны», даже когда OCR включён и `parser_output.visual_candidates` содержит результат chart extraction. `scripts` перезаписывает эту строку, поэтому существующий основной mock-тест проблему не замечает. Предложение: оставить `partial/not_measured`, но выбирать объяснение по parser metadata; различать запрошенный OCR, фактически полученные visual candidates и неподтверждённую полноту.
- 🟡 `extraction_core.py:374–392` — экспорт не проверяет согласованность ссылок parser metadata с переданными assets. `export_result(result, out)` для Docling успешно публикует `parser.json` с путями PNG/CSV, которых нет; то же происходит при передаче неполного словаря assets. CLI сейчас передаёт полный словарь, но публичная функция принимает такой вызов без ошибки и нарушает гарантию отсутствия неподкреплённых указателей. Предложение: перед публикацией проверить все `tables[].csv`, `figures[].image`, `visual_candidates[].csv/image` на наличие соответствующих assets; при отсутствии — `ValueError` и удаление staging.

## Что хорошо

- Optional import из CLI: default остаётся `pdfplumber`, Docling не нужен для импорта обычного пути; `--charts` без Docling отвергается.
- `BOTTOMLEFT` переводится в top-left правильно; неизвестные origins, нечисловые/нефинитные координаты и выход за страницу отклоняются. Table/cell bbox честно обозначается как bbox всей таблицы.
- ID таблиц/картинок сохраняют исходный индекс коллекции даже при пропусках; crop извлекается по этому же индексу. Пути создаются приложением, а не берутся из parser payload.
- Chart payload не попадает в текстовые `sources`; кандидаты имеют `visual_unverified/requires_review`, без фиктивной confidence. `chart2code` и `chart2summary` отключены.
- Частичный conversion status и несовпадение числа страниц запрещают публикацию. Отсутствующий crop также приводит к отказу.
- Staging в том же родительском каталоге, финальный rename и очистка при ошибках записи; ограничение путей и `allow_nan=False`. Ошибки самого converter маскируются без передачи потенциальных URL/credentials.

## Известные ограничения и границы проверки

- D001 parse и скачивание весов не запускались повторно. Live charts не проверены; fixture доказывает разделение каналов данных, но не качество распознавания осей, серий или чисел.
- Лимиты 40 МиБ / 150 страниц / 32 МиБ assets **не являются лимитом RAM**. `converter.convert` сначала строит весь документ с изображениями, `export_to_dict()` сериализует его целиком, PNG кодируется в `BytesIO` до проверки размера; сумма CSV проверяется после их накопления. В установленном docling-core `export_to_dict()` вызывает полный `model_dump`, без исключения image payload. Большие геометрические размеры страницы/распакованные изображения могут исчерпать память раньше проверки. Для недоверенных документов нужен отдельный ограниченный worker либо бюджет пикселей/ресурсов до рендера; CLI нельзя позиционировать как sandbox. Величина пикового RSS здесь не измерялась.
- Количество страниц не доказывает извлечение контента каждой страницы; `partial/not_measured` сохранено корректно. Отсутствие графиков в результате не доказывает их отсутствия в PDF.
- Составные/multipage элементы с несколькими provenance пропускаются с warning. Это явная потеря охвата, не выдуманная локализация.
- OCR использует `eng`; проверяется наличие executable, но не языкового пакета. Нет полной проверки реальной установки/инференса на всех заявленных версиях Python.
- Сохранение изображений, нормализация и сериализация выполняются вне маскирующего `try` вокруг `convert`; для неожиданных ошибок стороннего API не обещается тот же безопасный текст ошибки.
- Новый UI, полный алгоритм оцифровки SVG и переделка ранее проверенного core не требуются этим ревью.
