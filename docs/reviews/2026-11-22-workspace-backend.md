# Ревью backend научного рабочего пространства

Область: `chat.py`, `obsidian.py`, `pdf_quality.py`, `profile_assistant.py` и новые маршруты `server.py`.
Ревью выполнено чтением кода и сравнением контрактов. Тесты и исполняемые проверки не запускались по указанию пользователя.

## Находки

- 🟡 `src/viniti/obsidian.py:215`: `_result_value` отбрасывает `int`/`float`, поскольку `_text` принимает только строки. Настоящий `rag_api` отдаёт `metric_value` и `normalized_value` числами. При наличии `raw_value` экспорт подставляет исходное число рядом с нормализованной `metric_unit`, что может менять смысл величины; при отсутствии raw числовое значение исчезает. Аналогично `_publication` теряет числовой год. Нужно явно форматировать скалярные значения и сохранять согласованную пару значения и единицы.

- 🟡 `src/viniti/obsidian.py:149`: сборщик сущностей читает только `envelope.entities`, но `SolarStore._envelope` всегда записывает `entities: {}`. Поэтому настоящий solar-экспорт не создаёт заметок материалов/устройств/измерений, хотя они извлечены в таблицах; текущие архивы дают преимущественно статьи и авторов. Нужен адаптер реального solar-контракта, при этом локальные device IDs нельзя объединять между публикациями.

- 🟡 `src/viniti/pdf_quality.py:146`: чистота разбора считает успешным только `status == "ok"`. Каталожный `SolarStore._envelope` обозначает успешный документ как `done`. Каждый успешный solar PDF автоматически получает ERROR_PENALTY=0.5 и теряет 5 пунктов, хотя ошибки нет. Нормализовать статусы каталога перед расчётом.

- 🟡 `src/viniti/chat.py:103`: контекст использует только `text_sources`, игнорируя `recognized_sources`. После успешного Docling/OCR скана библиотека умеет показывать распознанные фрагменты через `solar_sources`, но чат по тому же документу сообщает, что пригодных источников нет. Нужно подключить распознанные источники с отдельным происхождением и не представлять их как проверенные буквальные цитаты исходного текстового слоя.

- 🟡 `src/viniti/chat.py:238`: `by_ref.get(ref)` выполняется до проверки строкового типа ref. Модель может вернуть допустимый JSON с `ref: []` или `ref: {}`; это вызывает TypeError, который маршрут `chat_post` не обрабатывает. Ответ HTTP обрывается вместо контролируемого отклонения неверного поля. Проверять ref до lookup. Аналогично следует защищать другие проверки принадлежности недоверенных JSON-значений множествам.

- 🟡 `src/viniti/profile_assistant.py:118`: аудит строгих профилей проверяет типы по FIELD_TYPES, где нет `id`, хотя `compile_profile` требует `id` для первичного ключа каждой таблицы. Каждый валидный встроенный универсальный профиль получает ложные `unknown_type` для своих ключей. Разделить допустимые типы предложений и типов полной схемы.

- ⚪ `src/viniti/obsidian.py:241`: значения Markdown-таблицы и подписи wikilinks не экранируют `|`, `[` и `]`. Имена и описания из статьи могут ломать колонки и создавать непредусмотренные связи в Obsidian. Использовать экранирование содержимого отдельно от генерации намеренных wikilinks.

## Остальные риски

- `chat.build_context` выбирает первые фрагменты с приоритетом таблиц, без поиска по вопросу. Это ограничивает полезность ответов по длинным статьям и библиотеке, даже когда нужный фрагмент сохранён.
- Проверка буквальности цитаты не доказывает, что все утверждения answer ею подтверждены. Поле `unverified` сейчас проверяет только наличие хотя бы одной принятой цитаты.
- Статус качества `ok` допускается даже без источников, если есть pages и не указан error. Это противоречит описанию «недостаточно данных» при неполных измерениях.
- Полный сетевой сценарий, миграция SQLite, конкурентные запросы и ZIP в реальном Obsidian не проверялись.

## Исправления после первого ревью

Числа и год Obsidian сохраняются, исходное значение не объединяется с нормализованной единицей. Solar-ссылки из результатов стали документными узлами без выдуманных атрибутов. Markdown/пути/wikilinks экранируются, имена стабильны. Статусы ok/done обработаны в оценке PDF, неизвестные данные дают insufficient. Чат использует распознанные источники и якоря результатов с происхождением; неверный JSON ref отклоняется безопасно. Тип id допустим для аудита, состав solar загружается из адаптера. Цитата помощника сохраняется до 600 символов. Универсальные разборы включены через адаптер с проверкой владельца.

Это записи по результатам чтения, не отчёт о выполнении тестов. Исполняемые проверки нового backend по условию задачи не запускались. Настоящая LLM не настроена; сетевой вызов и качество смыслового извлечения не проверены.
