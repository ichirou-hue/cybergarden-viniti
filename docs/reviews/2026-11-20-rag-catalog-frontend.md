## Вердикт

**Нужны правки, отдавать пользователю нельзя.** Один блокер (B1): штатная точка входа
`python server.py` (единственный способ запуска, описанный в README) теперь отдаёт пустую
страницу — модули и `/api/documents` не обслуживаются. Остальное — важные расхождения

них проявится ровно при подключении реального backend Мити.

Код при этом качественный: экранирование сделано правильно (весь серверный текст идёт через
`textContent`/`el`, ни одного `innerHTML`/`eval` в `static/` и `tools/` нет), отмена запросов
задумана верно, серверная пагинация не тянет конверт в браузер, раздача статики в моке
защищена от path traversal.

## 🔴 Блокеры

### B1. Штатный запуск `python server.py` отдаёт мёртвый UI: модули и `/api/documents` недоступны

- **Где:** `static/index.html:8` (`<script type="module" src="/app.js">`), `server.py:18-22`
  (белый список `ASSETS`: только `/`, `/style.css`, `/app.js`), `server.py:23` (единственный
  API — `/api/papers`), `README.md:16` (документированный запуск — `server.py`).
- **Что не так:** новый UI — ES-модули: `app.js` импортирует `./dom.js`, `./api.js`,
  `./catalog.js`, `./document.js`, `./evidence.js`, `./tracks/index.js`, те — `./ui.js`,
  `./tracks/rag.js`. `server.py` эти файлы не отдаёт, поэтому первый же `import` падает с 404
  и модульный граф не исполняется вообще (ошибок в UI не видно — пустой `#view`, пустая
  шапка, никакого сообщения). Проверено:

  ```
  GET /            -> 200
  GET /app.js      -> 200
  GET /api.js      -> 404  {"error": "Источник не найден."}
  GET /catalog.js  -> 404
  GET /tracks/index.js -> 404
  GET /api/documents?track=rag -> 404
  ```

  То есть «старый сценарий загрузить PDF → демо → подсветка» (гейт F1 в ADR) сломан, и
  единственный работающий путь — мок `tools/mock_api.py`, который в README не упомянут.
  `test_smoke.py` этого не видит: он ходит в `/api/papers`, а не в UI.
- **Почему важно:** это не «долг на потом» — пользователь/проверяющий по README получает
  белую страницу. Откат из ADR («`index.html` переключается одной правкой») сейчас
  отсутствует: старый `app.js` перезаписан.
- **Что сделать (одно из):**
  1. Минимальная правка `server.py` (или отдельный `serve.py` для этапа F1/F2): отдавать
     `static/**` по тому же безопасному правилу, что и `mock_api.py:293-300`, и добавить
     заглушки `/api/documents…` (можно проксировать в мок-данные);
  2. сохранить старый UI как `/legacy` (или `app.legacy.js` + отдельный `index-legacy.html`)
     до появления реального API — тогда откат воспроизводим;
  3. если решено жить на моке — явно описать это в README как единственный способ запуска
     UI и не считать `server.py` точкой входа демо. Это худший вариант, но хотя бы честный.
- Дополнительно: в `index.html` нет `<noscript>` и обработчика `window.onerror` для
  сбойной загрузки модулей — добавьте текстовое «Не удалось загрузить интерфейс, обновите
  страницу», чтобы поломка не выглядела как пустой экран.

## 🟡 Важное

### F1. Просроченные debounce-таймеры переписывают URL чужого экрана и портят состояние фильтров

- **Где:** `static/catalog.js:77-85`, `static/document.js:270-278`, `static/document.js:475-480`;
  запись в URL — `catalog.js:118-121`, `document.js:286-290`, `document.js:449`.
- **Что не так:** таймер поиска (250 мс) не снимается при уходе с экрана, а `load()`
  безусловно вызывает `ctx.patch(...)`, который парсит **текущий** hash. Если уйти со экрана
  в пределах 250 мс, колбэк выполнится уже на другом экране и допишет в его URL параметры
  прошлого экрана. Воспроизведено дважды:
  - каталог: ввести `D014`, сразу кликнуть публикацию → `#/doc/rag:d020?track=rag&q=D014`;
  - карточка: ввести `Recall` в поиск результатов, сразу уйти в каталог →
    `#/?track=rag&sort=publication_id&q=Recall`.

  Пока экран уже отрисован, визуально всё «нормально», но URL врёт: перезагрузка или
  отправка ссылки открывает карточку с фильтром `q=D014` (0 строк) или каталог с `q=Recall`
  (пустой список), причём поисковое поле при этом пустое/не соответствует URL.
- **Почему важно:** «URL как состояние» — ключевое требование ADR; именно шарингом ссылки
  проверяется работа. Симптом «пустой каталог без причины» на защите выглядит как баг данных.
- **Что сделать:** в каждом экране завести teardown: `const off = () => clearTimeout(timer)`;
  подписаться на `ctx.signal.addEventListener("abort", off, {once: true})`; в начале каждого
  `load()` — `if (ctx.signal.aborted) return;`. Дополнительно `ctx.patch` уместно вызывать
  только когда экран «владеет» маршрутом (проверка `location.hash` начинается с ожидаемого
  префикса) либо перевести `patch` на явную передачу пути.

### F2. Нет защиты от «устаревшей отрисовки» после `await` — старый экран может перезаписать новый

- **Где:** `static/app.js:82-101` (после `await renderDocument(...)` / `await renderCatalog(...)`
  нет проверки `ctx.signal.aborted`); `static/app.js:77-79` создаёт новый `AbortController`
  на каждый маршрут, но старый промис продолжает выполняться.
- **Что не так:** `hashchange`-обработчик не дожидается предыдущего `route()`. Если запросы
  старого экрана успели разрешиться (или упали не с `AbortError` — см. F5, где `facets`
  глотает `AbortError`), продолжение старого `route()` дорисует свой экран поверх нового.
  Отдельный случай: `app.js:87` — после `await` может открыться диалог доказательства
  **предыдущего** документа уже на другом экране.
- **Почему важно:** ADR прямо требует «устаревшие ответы не должны перерисовывать экран»;
  окно узкое, но именно оно даёт «мигание чужим документом» на быстрых переходах.
- **Что сделать:** в `route()` завести `const signal = app.controller.signal` и перед каждой
  отрисовкой проверять `if (signal.aborted) return;` (включая место перед `openEvidence`).
  В `document.js:23-24` не глотать `AbortError` в `.catch` фасетов — пропускать его дальше
  или проверять `ctx.signal.aborted`.

### F3. Внутриэкранные запросы не сериализованы: два `load()` одного экрана могут прийти в обратном порядке

- **Где:** `static/catalog.js:117-135`, `static/document.js:285-304`.
- **Что не так:** `AbortController` живёт на маршрут, а не на запрос. Быстрое «ввёл строку →
  сменил статус/сортировку» порождает два параллельных `getJSON` с одним сигналом; какой
  ответ вернётся первым, неизвестно. Медленный первый ответ перетрёт более новый результат
  (и `ctx.patch` от него же перепишет URL назад).
- **Почему важно:** это классические «прыгающие» результаты при поиске, которые трудно
  объяснить пользователю; на реальном backend с разной латентностью фильтров проявится
  постоянно.
- **Что сделать:** на экран держать `let request = 0` и `const id = ++request` перед fetch;
  после `await` — `if (id !== request) return;`. Либо отдельный `AbortController` на каждый
  запрос, отменяющий предыдущий в пределах экрана.

### F4. Загрузка и демо не передают область (`X-Track`), а `openDocument` игнорирует `track` из ответа

- **Где:** `static/api.js:24-31` (`uploadPDF` без `X-Track`), `static/api.js:33-35` (`openDemo`
  без `X-Track`), `static/app.js:118-121` (`?track=${app.track}` вместо `document.track`).
- **Что не так:** ADR-0008 (§ «Контракт API») требует `POST /api/documents` с `X-Track` и
  `X-Filename`; в ответе есть поле `track`, и мок его отдаёт. UI отправляет только
  `X-Filename` и при переходе подставляет текущую область окна, а не область документа.
  Проверено на моке: `POST /api/documents` c `X-Track: solar` создаёт `rag:статья` — мок
  заголовок игнорирует (`tools/mock_api.py:457-476`).
- **Почему важно:** как только появится `tracks/solar.js`, загрузка PDF или «Демо» из
  солнечной области уведут в RAG-карточку с `?track=solar` — неверный дескриптор, неверные
  колонки, «← Каталог» вернёт в другую область. Это ровно тот класс ошибок, который ADR
  закрывает требованием «`document_id` включает `track`».
- **Что сделать:** `uploadPDF(file, track)` → `X-Track: track`, `openDemo(track)` → то же;
  в `openDocument` брать `document.track || app.track`; в моке — учитывать `X-Track` (или
  явно зафиксировать в docstring, что мок однодоменный, и не считать это проверкой).

### F5. Дескриптор выбирается по `?track=`, с молчаливым фолбэком на первую область

- **Где:** `static/app.js:66-75`; `static/document.js:31` (хлебная крошка использует
  `ctx.descriptor.track`).
- **Что не так:** `const wanted = params.track || app.track; const descriptor =
  descriptors.find(...) || descriptors[0]`. Любой документ, открытый без `track` или с
  неизвестным `track`, рендерится дескриптором RAG, при этом `app.track` становится `rag`,
  а в URL остаётся исходный `track`. Проверено: `#/doc/rag:d020?track=solar` показывает
  RAG-колонки и подсвечивает в переключателе RAG.
- **Почему важно:** после появления Solar «ссылка на документ, скопированная из адресной
  строки без `track`» (а `evidence.js:13-18` как раз формирует ссылки из `location.hash`)
  откроется с чужими колонками и без ошибки. ADR это запрещает («`D001` двух областей —
  разные документы; без `track` в ключе UI смешает области»).
- **Что сделать:** выводить область из префикса `document_id` (`id.split(":")[0]`) как
  приоритетный источник, а `?track=` использовать только для каталога; неизвестный `track`
  — явная ошибка «область не подключена», без фолбэка.

### F6. Глубокие ссылки на источник опираются на эндпоинт `anchors/<id>.json`, которого нет в контракте ADR

- **Где:** `static/evidence.js:36-38`; `static/app.js:81-87`; `tools/mock_api.py:424-431`
  (мок реализует `.json`, ADR-0008 § «Контракт API» — только `anchors/{source_id}.png`);
  `docs/adr/0008-rag-catalog-ui.md:108,139`.
- **Что не так:** если Митя реализует ровно то, что записано в ADR, то при открытии
  `#/doc/<id>/source/<sid>` (сценарий F3/F5 и просто шаринг ссылки) `getJSON` вернёт 404,
  ошибка всплывёт в `route()` и **заменит весь экран карточки** на «Не удалось загрузить
  данные» — документ и вкладки пропадут. Кнопки «Стр. N»/«Заголовок» в таблице работают
  (у них есть `source`), то есть ломается только глубокий вход.
- **Почему важно:** (а) контракт не согласован — мок обещает фронту больше, чем будет в
  backend; (б) отказ глубокой ссылки деградирует катастрофически, а не до «номер страницы +
  цитата», как требует ADR.
- **Что сделать:** либо добавить `GET …/anchors/{source_id}.json` в контракт ADR (и
  согласовать с Митей), либо не ходить за якорем: открывать диалог с тем, что есть
  (страница из URL, цитата — по загруженным результатам), а `openEvidence` вызывать в
  `try/catch` с локальным сообщением вместо глобального экрана ошибки.

### F7. Контракт мока расходится с ADR в трёх местах, которые UI уже ждёт: `limit/offset` каталога, `counts.by_status`, `record_ids`/`source` у замечаний

- **Где:** `tools/mock_api.py:316-329` (каталог игнорирует `limit`/`offset`; проверено:
  `?limit=2&offset=2` → 8 items), `tools/mock_api.py:362` (`counts` без `by_status`),
  `tools/mock_api.py:386-389` (у замечаний нет `record_ids` и `source`).
- **Что не так:**
  - серверная пагинация — центральное требование ADR («28k строк не должны попадать в
    браузер»); мок её не реализует, поэтому вторая страница каталога и «Далее» на каталоге
    не проверяются вообще, а баг пейджера (см. F13) не виден ни на моке, ни в jsdom-харнессе;
  - `counts.by_status` в ADR обязателен, UI его не использует — но контракт должен быть
    согласован, иначе Митя сделает по-своему;
  - из-за отсутствия `record_ids` ветка «переход к результату с подсветкой» (`document.js:417-420`)
    — мёртвый код: харнесс её не проверяет, потому что кликать не по чему.
- **Почему важно:** мок заявлен как «повторяет будущий контракт байт-в-байт» (ADR § Риски);
  сейчас он повторяет его только там, где удобно UI.
- **Что сделать:** реализовать в моке `limit/offset` для `/api/documents` (и для `/issues`
  честно применить `limit`), добавить `by_status`, `record_ids`, `source` в фикстуры
  замечаний; добавить в харнесс кейсы «вторая страница каталога» и «клик по `record_id`».

### F8. Клик по `record_id` в «Замечаниях» не сбрасывает фильтры и ничего не подсвечивает

- **Где:** `static/document.js:417-420` (`ctx.go({tab: "results", q: id, page: ""})`).
- **Что не так:** `go` мержит параметры, поэтому `metric`, `dataset`, `config`, `status`,
  `issues` с прошлой выборки остаются. Если пользователь смотрел «Recall@5 + только с
  замечаниями», клик по записи из другого среза даёт пустую таблицу без объяснения. ADR же
  требует «ссылки на `record_ids` (переход к результату **с подсветкой**)»; подсветки и
  якоря/`scrollIntoView` нет вовсе.
- **Что сделать:** переход в отдельный параметр (`?result=R001`) со сбросом
  `metric/k/dataset/config/status/issues`, прокруткой к строке и визуальным выделением
  (класс + `aria-current`/`tabindex=-1` + фокус), либо фильтр по `result_id` на сервере.

### F9. Маршруты вкладок карточки не совпадают с ADR (`tab=` вместо `view=`)

- **Где:** `static/document.js:26,50`; ADR-0008:59-62 (`?view=entities&entity=configurations`,
  `?view=issues`, `?view=sources&kind=table`).
- **Что не так:** ссылки, собранные по ADR (документация, чек-лист демо, задачи Мите/Егору),
  молча открывают вкладку «Результаты». Проверено: `#/doc/rag:d020?track=rag&view=issues`
  → активная вкладка «Результаты». То же с `?view=sources&kind=table`.
- **Почему важно:** ADR — согласуемый артефакт; расхождение имён параметров между
  документом и кодом ломает и демо-сценарий, и работу второго разработчика.
- **Что сделать:** либо переименовать в коде на `view=`, либо поправить ADR. Заодно
  определиться с `entity=`/`kind=`/`sq=` и зафиксировать полный список параметров в ADR.

### F10. Вкладки: неполный ARIA-паттерн и потеря фокуса при переключении

- **Где:** `static/document.js:46-53` (у кнопок `role="tab"` нет `aria-controls`,
  `id`, стрелочной навигации; у `.tab-body` нет `role="tabpanel"`, `aria-labelledby`,
  `tabindex="0"`); `static/style.css` — нет `:focus-visible` (в утверждённом прототипе
  `prototypes/rag-catalog/variant-a.html` есть и `:focus-visible`, и `.skip`, и `.sr-only`).
- **Что не так:** переключение вкладки — это полный ре-рендер (`ctx.go` → `route`), кнопки
  пересоздаются, фокус уходит в `body`: клавиатурный пользователь после Enter на вкладке
  «теряет» место. `role="tab"` без `tabpanel` и без стрелок — это роль без поведения.
- **Почему важно:** ADR:143 требует «навигация с клавиатуры, фокус в диалоге, читаемость
  при 200 %». Диалог в порядке (нативный `dialog`, Esc, `aria-labelledby` — проверено), а
  вкладки и общая навигация — нет.
- **Что сделать:** либо отказаться от `role="tablist"/tab` и использовать обычные ссылки
  (`<a href="#/doc/...&view=...">`) — дешевле и корректнее для hash-роутера; либо
  дореализовать паттерн: `id`/`aria-controls`/`tabpanel`, roving `tabindex`, стрелки
  Left/Right/Home/End, и после перерисовки возвращать фокус на активную вкладку.
  Плюс перенести из прототипа `:focus-visible`, `.skip`, `.sr-only` и ставить фокус на
  `h1` (или `main[tabindex="-1"]`) после смены маршрута.

### F11. Шапка карточки не показывает `in_scope`/причину исключения и DOI; статус `running` не обработан

- **Где:** `static/document.js:29-41` (шапка), `static/document.js:69-93` (`noticeBlock`).
- **Что не так:** по ADR:80 в шапке обязательны `in_scope` (+ причина исключения) и DOI —
  их нет нигде (мок их отдаёт: `publication.in_scope`, `exclusion_reason`, `doi`). По
  ADR:96 для `running` нужен баннер и **блокировка экспорта** — ни баннера, ни блокировки:
  ссылки PDF/JSON/CSV рендерятся для любого статуса (проверено на `failed`: `CSV` ведёт на
  пустой файл мока). В `ui.js:3-9` статус `running` есть, но нигде не используется по смыслу.
- **Почему важно:** `in_scope` — это содержательный ответ «почему статьи нет в выборке»;
  без него карточка не объясняет исключение. Экспорт недособранной статьи на защите
  выглядит как ошибка данных.
- **Что сделать:** добавить в `metaLine`/`doc-actions` бейдж `in_scope` и текст
  `exclusion_reason`, DOI-ссылку (`https://doi.org/<doi>`); в `noticeBlock` — ветку
  `running` («идёт обработка, экспорт недоступен»); в `doc-actions` не рендерить (или
  `aria-disabled`) ссылки экспорта при `running`/`queued`.

### F12. Отказ фасетов молча убирает все фильтры результатов

- **Где:** `static/document.js:21-25` (`.catch(() => ({metrics: [], …}))`),
  `static/document.js:230-232` (`if (!options.length) continue;`).
- **Что не так:** `404/500` на `/facets` (а он не реализован в `server.py` вовсе) превращается
  в «фасетов нет» — панель фильтров исчезает целиком, без сообщения; при этом результаты
  показываются как будто фильтров и не было. Пользователь не отличит «в статье нет метрик»
  от «фасеты не загрузились».
- **Что сделать:** отличать «пустой список» от «ошибка»: при ошибке показывать
  предупреждение в панели (`role="status"`) и, пока фасетов нет, хотя бы сохранять
  `status`-фильтр из дескриптора (он перечислимый).

### F13. Ошибка в «Сущностях»/«Замечаниях»/«Фрагментах» сносит весь экран карточки; пейджер и пустое состояние остаются от прошлой выборки

- **Где:** `document.js:377`, `396`, `450` — `getJSON` без локального `try/catch`;
  `document.js:299-304` — при ошибке не очищаются `pager` и `placeholder`;
  `document.js:219,314` и `catalog.js:29` — `page` из URL не ограничивается диапазоном.
- **Что не так:**
  - ошибка любой не-«результатной» вкладки всплывает в `app.js:95-101` и заменяет всю
    карточку (шапка, вкладки, кнопки экспорта) на «Не удалось загрузить данные»; переключить
    вкладку, чтобы посмотреть остальное, уже нельзя;
  - при ошибке загрузки результатов внизу остаются кнопки пейджера от прошлой выборки, а
    под таблицей — прежнее «Ничего не найдено…»;
  - `?page=99` даёт `Найдено 408 · страница 99 из 9` (проверено), у каталога — `Публикаций: 8`
    при `99 / 1` в пейджере; «Назад» ведёт на 98 и так далее. На моке каталога это не
    заметно, потому что мок игнорирует `offset` (F7), но с настоящим API проявится сразу.
- **Что сделать:** обернуть каждый `getJSON` вкладки в `try/catch` с сообщением внутри
  `body`; при ошибке очищать `pager`/`placeholder`; после получения `total` зажимать
  `state.page = Math.min(state.page, pages)` и перезапрашивать/писать URL корректно.

### F14. Вкладка «Фрагменты PDF»: `sq` пишется в URL, но не читается; цитата берётся из `quote`, а в остальном UI — из `fragment`

- **Где:** `static/document.js:449` (`ctx.patch({kind, sq})`), `document.js:466`
  (`item.quote`), сравните `document.js:36-37,165-166` (`fragment`).
- **Что не так:** `sq` не восстанавливается в поле поиска (и не попадает в `parse`-логику
  экрана), то есть параметр мёртвый: по ссылке `?view=sources&sq=Recall` откроется пустой
  поиск и полный список. Поле цитаты: у результатов — `source.fragment`, у фрагментов —
  `item.quote`; контракт `/sources` в ADR не описан вообще, а `evidence.js:43` умеет оба
  варианта. Мок отдаёт `quote`, реальный backend по аналогии с остальным контрактом,
  скорее всего, отдаст `fragment` → колонка «Цитата» будет пустой.
- **Что сделать:** либо убрать `sq` из URL, либо проставлять `search.value = ctx.params.sq`
  при инициализации; нормализовать `item.fragment ?? item.quote`; и внести `/sources`
  (+ формат элементов) в контракт ADR.

### F15. Вкладка «Сущности»: сырые имена полей в заголовках, нет ссылки «показать результаты конфигурации», массивы печатаются как `a,b`

- **Где:** `static/document.js:384-389`.
- **Что не так:** `Object.keys(data.items[0])` даёт `config_id / label / detail` в шапке
  таблицы (проверено), то есть интерфейс показывает имена полей API; ADR:94 требует «таблицы
  по типам области со ссылкой “показать результаты этой конфигурации/прибора”» — ссылки нет;
  `String(item[key])` для массива даст `a,b`.
- **Что сделать:** колонки брать из дескриптора (`entities[].columns` с `label` и
  рендерером), для `config_id`/`dataset_id` — ссылку на «Результаты» с соответствующим
  фильтром, массивы форматировать через `join(", ")`.

### F16. Мок: необработанные `ValueError` роняют соединение; нет валидации `Content-Type` при загрузке

- **Где:** `tools/mock_api.py:380` (`int(single.get("limit", 50))`), `mock_api.py:425`
  (`int(key[:-5])`), `mock_api.py:459-466` (POST без проверки типа).
- **Что не так:** проверено: `GET /api/documents/rag:d020/results?limit=abc` → соединение
  обрывается (`curl` код `000`, трейсбек в stderr), то же для
  `/anchors/foo.json`. `POST /api/documents` с `Content-Type: text/plain` принимается, хотя
  `server.py:85-87` отвечает `415`. Инструмент разработки, но именно он — исполняемая
  спецификация контракта, и UI на такие ответы рассчитан («Ошибка 500» с текстом).
- **Что сделать:** обернуть парсинг чисел в `try/except ValueError → 400`, проверять
  `get_content_type()` как в `server.py`, добавить лимит на `Content-Length`.

## ⚪️ Мелочи

1. `static/api.js:3-13` — если сервер вернул `200` с не-JSON телом (например HTML вместо
   `application/json`), пользователь увидит `Unexpected token '<'`. Стоит ловить
   `SyntaxError` и отдавать человеческое «Сервер вернул неожиданный ответ».
2. `static/app.js:118` — параметр функции называется `document` и затеняет глобальный
   `document`; сейчас безопасно, но это ловушка для следующей правки.
3. `static/app.js:84` — `decodeURIComponent` вне `try`: на `#/doc/%E0%A4%A` экран
   превращается в «Не удалось загрузить данные» с текстом `URI malformed` (проверено).
   Стоит трактовать как «Страница не найдена» и добавить ссылку на каталог.
4. `static/app.js:95-101` — экран глобальной ошибки не содержит ссылки «К каталогу»
   (есть только бренд в шапке) и дублирует текст в `#status`.
5. `static/catalog.js:118-121` — `sort=publication_id` (значение по умолчанию) попадает в
   URL при первом же рендере: `#/?sort=publication_id`. Не критично, но шум в ссылках;
   лучше писать только нечитаемые по умолчанию значения.
6. `static/catalog.js:138-140` и `162-168` — «Ничего не найдено. Проверьте фильтры…» и
   «Ничего не найдено.» дублируются в счётчике и в пустом состоянии; кнопка «Сбросить
   фильтры» ведёт на `#/` и сбрасывает всё, включая область/сортировку (в ADR пустое
   состояние описано с кнопками «Загрузить PDF»/«Открыть демо» — их нет, хотя форма в шапке
   есть).
7. `static/ui.js:27-29` — `seconds(0)` печатает «—», хотя 0 мс — валидное значение
   (`if (!ms) return "—"`). Для упавшей обработки корректнее «—», для «мгновенно» — «0,0 с»;
   достаточно явно это зафиксировать.
8. `static/ui.js:38-44` — `plural` не обрабатывает отрицательные/дробные значения; сейчас

9. `static/dom.js:1-16` — `value` ставится через `setAttribute`; для `<input>` это
   «значение по умолчанию», а не текущее. Работает только потому, что `el` вызывается до
   монтирования. Стоит особо обрабатывать `value`/`checked` как свойства.
10. `static/document.js:139-144` — хук `descriptor.cells` не документирован и не используется
    ни одним дескриптором; либо задокументировать в ADR (это то, что понадобится Егору),
    либо убрать до появления потребителя.
11. `static/document.js:16` — `KIND_LABELS` захардкожены в карточке, хотя по ADR типы
    фрагментов — представление области; при переносе в дескриптор `document.js` не придётся

12. `static/document.js:59-66` — для статьи с `pages: 0` в мете «0 стр.», для `failed` это

14. `static/document.js:29-41` — подпись ссылки «CSV» без «(область)», как в ADR:80;
    `PDF` ведёт на `/api/documents/<id>/pdf`, которого нет в контракте ADR (мок его умеет),

15. `static/document.js:294` — вложенный шаблон
    `` `${`/api/documents/${encodeURIComponent(ctx.docId)}`}/results` `` читается тяжело;

16. `static/tracks/index.js:7-14` — `catch` глотает **любую** ошибку динамического импорта:

27. Имена/документация: ADR и `docs/adr/0008…md:158,237` говорят `tools/mock_server.py`,

## F17 (инструменты): состояние функционального харнесса

- **Где:** `/tmp/opencode/uitest/harness.mjs` (вне репозитория), копия `static/` рядом.

    4xx/5xx экранов, переключение области, вкладка «Сводка» с пустыми фасетами, `page` за
    пределами диапазона, загрузка файла.

## Что проверено, претензий нет

- **XSS/экранирование.** В `static/` и `tools/` нет ни одного `innerHTML`, `outerHTML`,
  `insertAdjacentHTML`, `document.write`, `eval`, `new Function`. Весь серверный текст
  (`title`, `error`, `description`, `note`, `fragment`, `publication_id`, имена полей)
  идёт через `el(..., {text})`/`textContent` или текстовые узлы (`dom.js:6,13`). Значения
  атрибутов ставятся через `setAttribute` — инъекция через кавычки невозможна.
  Единственное мягкое место — `href` из `summary.export?.json` (`document.js:38`):
  это данные API, но валидировать схему/префикс `/api/` не помешает.
- **Отмена запросов в общем виде.** `AbortController` на маршрут + `abort()` перед новым
  (`app.js:77-79`), сигнал протянут в `getJSON` и в `openEvidence`; ветки `AbortError`
  обработаны в `catalog.js:130` и `document.js:300`; `route()` глотает `AbortError`
  (`app.js:96`). Замечания F1-F3 — про таймеры, последовательность и проверку после `await`,
  а не про отсутствие отмены.
- **URL как состояние (базовый механизм).** `parse`/`buildHash`/`patch`/`go` работают
  предсказуемо, `compact` вычищает пустые значения, `encodeURIComponent` для `rag:d020`
  корректен (`rag%3Ad020` ↔ `rag:d020`), обратное декодирование в `route` работает,
  `history.replaceState` для фильтров и `location.hash` для навигации используются по делу.
  Восстановление адреса при закрытии диалога работает в обе стороны (проверено: вход с
  фильтрами и глубокой ссылкой).
- **Серверная пагинация/объём.** Каталог и таблица результатов запрашивают страницы по
  50 строк, конверт статьи в браузер не грузится, `D014` (28 649) листается по 50 (харнесс).
- **Раздача статики в моке.** `mock_api.py:293-300`: `resolve()` + проверка `parents`
  закрывает `../`, `%2e%2e`, `//etc/passwd`, `/static/../server.py` (проверено — 404).
  `X-Content-Type-Options: nosniff` на всех ответах, MIME для `.js` — `text/javascript`.
- **Детерминированность мока.** `reportlab` с `invariant=True` (`mock_api.py:235`) — PDF
  байт-стабилен; данные строятся детерминированно из `POOL`, кэши `FACETS`/`ANCHOR_INDEX`
  не зависят от порядка запросов (кроме `BY_ID` после POST — ожидаемо).
- **Поведение по статусам (частично).** `failed` и `partial` дают баннеры и текст причины;
  скан без OCR даёт явный баннер и пустое состояние в «Фрагментах» (харнесс + проба).
- **Пустые состояния результатов.** Различаются «нет результатов в статье» (подсказка
  дескриптора) и «по фильтрам ничего нет» (`document.js:308-313`).
- **Backend не затронут:** `python -m unittest -v` — 2/2 ok.

- Реальный браузер: фактический фокус в `<dialog>`, Esc, sticky-заголовки таблиц, поведение

  debounce-поиске).
- Solar-область: дескриптора нет, фикстур мока для solar нет — переключение областей,
  сохранение фильтров при переключении (ADR:201) и `X-Track` проверить не на чем.
- Настоящий каталог на 90 документов и реальные ответы Мити (сейчас всё: 8 фикстур, один
  трек, `limit/offset` игнорируются).
- Fallback «PNG 404 → номер страницы + цитата»: мок всегда отдаёт картинку, ветка
  `evidence.js:31-34` не исполнялась.
- 404/500 от реального API во всех вкладках карточки (проверял только «документ не найден»).
- Поведение при отключённой сети/офлайне (заявлено в ADR как обязательное).

## 5 главных пунктов

1. **B1** — `python server.py` (README) отдаёт пустую страницу: модули `static/*.js` и
   `/api/documents` не обслуживаются. Без этого правки UI нет смысла отдавать.
2. **F1 + F3** — таймеры debounce переживают уход с экрана и переписывают URL чужого
   экрана (`?q=D014` на карточке, `?q=Recall` в каталоге), конкурирующие `load()` одного
   экрана не сериализованы. Это подрывает главное обещание «ссылка = состояние».
3. **F4 + F5** — область (`track`) не передаётся при загрузке/демо и не выводится из
   `document_id`: с появлением Solar это даст документы в чужой области и чужие колонки.
4. **F6 + F7 + F9** — контракт мока расходится с ADR (`anchors/*.json`, `limit/offset`,
   `record_ids`, `by_status`, `view=` vs `tab=`): фронт обещает то, чего в backend не будет,
   а серверная пагинация и «переход к записи» остаются непроверенными.
5. **F10 + F11 + F14/F15** — доступность и полнота карточки недотягивают до ADR:
   вкладки без `tabpanel`/стрелок и с потерей фокуса, нет `:focus-visible`/skip-link из
   прототипа, нет `in_scope`/DOI и баннера `running`, «Фрагменты» и «Сущности» показывают
   имена полей API.
