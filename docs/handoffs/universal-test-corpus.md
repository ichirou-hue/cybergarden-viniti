# PDF для проверки универсального профиля

Локальный комплект: `docs/materials/universal-participant-kit/`, рядом с существующими solar/rag participant kits.

- `test/U001.pdf` ... `U010.pdf`: 10 разнотемных научных статей.
- `submission_template/`: три пустых CSV, полный `profile.json`, JSON Schema ответа модели `schema.json`.
- `submission_drafts/U001/` ... `U010/`: отдельные пустые CSV для каждой статьи.
- `manifest.json` и `verification.json`: URL, размер, SHA-256, страницы и итоги технических проверок.
- `README.md`: структура, правила заполнения, ссылки на статьи.

Шаблоны соответствуют `profiles/universal.json`: studies, results, findings. Это отдельный формат для универсального профиля, не официальные семь таблиц solar/RAG. Доказательства полей задаются в `field_sources` JSON-ответа согласно schema.json. Пустые CSV не являются эталонной разметкой.

Подборка разнообразная, но не статистически случайная. Она предназначена для проверки независимости от двух тем кейса. Количество статей не заменяет измерение полноты/точности на ручном эталоне.

Воспроизведение из корня репозитория:

```sh
.venv/bin/python -X utf8 tools/universal_corpus.py
.venv/bin/python -X utf8 tools/universal_corpus.py --verify-only
```

На Windows используйте `.venv\Scripts\python.exe -X utf8`.

PDF и локальные черновики исключены из Git существующим правилом `docs/materials/`. В репозитории сохраняются загрузчик и `tools/fixtures/universal-papers.json` с первичными URL и контрольными суммами. Они позволяют получить тот же комплект на другой машине. Загрузчик не перезаписывает имеющиеся PDF/CSV и сообщает о расхождении схемы/контрольной суммы.

Проверяются только: PDF-сигнатура, читаемость страниц, наличие текста, уникальность файлов, контрольные суммы и соответствие схем/заголовков CSV. Настоящая LLM не вызывается; заполнение научных таблиц и качество смыслового извлечения не подтверждены.
