# Разработка и запуск solar extractor

Для нового профильного CLI, режимов `scripts`/`auto`/`model` и оценки см. [гайд profile extraction core](2026-11-20-profile-core-guide.md). Описанный ниже standalone solar CLI `solar_extract.py` сохранён и остаётся совместимым.

Документ описывает текущий standalone vertical slice для извлечения данных из одного текстового PDF. Он использует OpenRouter, пишет локальные JSON/CSV-артефакты и не меняет общий backend, library, server или UI. Контракт с Митей provisional; это не интеграция с серверным API.

## Установка и проверка

Используйте окружение проекта и существующий `requirements.txt`:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python solar_extract.py --help
```

Solar добавляет модули в корень репозитория и не добавляет отдельные зависимости сверх `requirements.txt`. Windows-путь к Python: `.\.venv\Scripts\python.exe`.

## Настройка OpenRouter

Для сетевого запуска нужны переменные `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`. Модель выбирает пользователь: укажите точный slug, доступный в OpenRouter; здесь намеренно не предлагается default model.

```bash
export OPENROUTER_API_KEY='...'
export OPENROUTER_MODEL='точный-slug-модели'
```

CLI не загружает `.env` автоматически. Файл `.env` исключён из Git. Если вы храните значения в нём, явно загрузите их в окружение перед запуском, не помещайте секрет в документацию, shell history или результаты. Не читайте и не публикуйте содержимое чужого `.env`.

Перед отправкой текста PDF провайдеру убедитесь, что такая передача допустима для документа.

## Подготовка без API

`--prepare` извлекает локальные источники и записывает `request.json`; API и CSV не используются:

```bash
.venv/bin/python solar_extract.py article.pdf -o prepared-request --prepare
```

Для этого режима ключ не нужен и сетевого обращения нет. Каталог результата должен быть новым. Запрос содержит текст источников, поэтому обращайтесь с ним как с содержимым документа.

## Полный запуск

```bash
.venv/bin/python solar_extract.py article.pdf -o solar-result
```

`-o`/`--output` должен указывать на новый каталог. При успехе там находятся `result.json` и семь CSV: `publications.csv`, `materials.csv`, `devices.csv`, `layers.csv`, `measurements.csv`, `results.csv`, `issues.csv`. CSV используют заголовки шаблона, UTF-8 и значения полей-строк; неизвестное значение — пустая строка `''`, не `null`.

Пример результата в тестах и документации — синтетический, не запись корпуса и не подтверждение live-качества на реальных статьях.

## Текущий контракт и проверка источников

Реализованные функции для provisional-контракта: `prepare_pdf`, `messages`, `complete`, `finalize`, `analyze_pdf`. JSON envelope содержит `schema_version: "solar-1"`, `track: "solar"`, `publication_id`, `sha256`, `pages`, `sources`, `tables`, `evidence`, `warnings`, `extraction`.

Проверка источника буквальная: значения source IDs сверяются с источниками документа; для результатов проверяются страница и наличие `source_fragment` в тексте источника, а исходное число — в цитате. Координаты прикрепляет локальный PDF extractor. Это не field-level semantic/header verification и не гарантия научной правильности, полноты или правильной связи сущностей. `evidence` — внутренний индекс источников по записи, не отдельный field-level audit trail.

## Ограничения и параметры

- PDF не больше 40 МиБ и не больше 150 страниц (ограничение извлечения страниц — из используемого `pdf_source`).
- В запрос передаётся весь документ; по умолчанию бюджет — 200000 символов. При превышении выполнение завершается ошибкой, текст не обрезается.
- OCR, chunking, пакетная обработка нескольких PDF и обработка графиков не реализованы.
- `--max-tokens` по умолчанию 16000 (допустимо 1–64000); `--timeout` по умолчанию 90 секунд (1–600); `--retries` по умолчанию 2 повтора (0–3). Повторяются временные сетевые ошибки и HTTP 429/500/502/503/504 с ограниченной задержкой. Общий deadline и jitter не реализованы.
- OpenRouter может тарифицировать запросы и повторные попытки; учитывайте выбранную модель, размер передаваемого текста и квоту.
- Модель отвечает в JSON object режиме. Ошибки HTTP, timeout/сети, незавершённый ответ, невалидный JSON, превышение лимита ответа или ошибка валидации завершают команду ненулевым кодом; ошибки API не выводят тело ответа.

Локальные тесты проверяют логику и не заменяют проверку live-качества. Провайдер/ключ/модель пока не настроены, а качество на реальных документах не измерено.

Для тестов:

```bash
.venv/bin/python -m unittest test_solar -v
```
