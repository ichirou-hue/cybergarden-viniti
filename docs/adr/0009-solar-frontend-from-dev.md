# ADR-0009. Перенос экрана «Паспорт статьи» из `dev` рядом с RAG-каталогом

- **Статус:** принято
- **Дата:** 2026-11-20
- **Владелец:** Илья Б (frontend)
- **Связанные решения:** ADR-0008 (RAG-каталог и карточка результата)
- **Область:** `static/`, маршруты статики в `server.py` и `tools/mock_api.py`, `README.md`. Контракт API и бизнес-логика не меняются.

## Контекст и проблема

В ветках сложились два независимых фронтенда с разными задачами и разным визуальным языком:

| Ветка | Файлы | Что делает | Визуал |
|---|---|---|---|
| `feature/rag-frontend` | `static/index.html`, `app.js`, `catalog.js`, `document.js`, `evidence.js`, `ui.js`, `style.css`, `tracks/*` | каталог публикаций, карточка статьи, фильтры, просмотр доказательств; данные — серверный API (`/api/documents…`, мок `tools/mock_api.py`) | светлая тема, зелёный акцент, плотные таблицы |
| `dev` | `static/solar.html`, `solar.css`, `solar.mjs`, `solar-ui.mjs` | один экран «Паспорт статьи»: импорт JSON/CSV-экспорт, привязка PDF, таблица результатов и карточка; данные — файл в браузере | тёмная тема, лаймовый акцент, крупная типографика, hero-блок |

Файлы `static/*` в ветках не пересекаются по именам, поэтому git-конфликта в разметке и стилях нет. Пересекаются только общие точки: ключ `/` в `ASSETS` (`server.py`) и текст `README.md`. Общая база — `main@589c2f9`, `dev` ушёл вперёд на 4 фронтенд-файла и правку маршрутов, моя ветка — на каталог, мок-API и UI-тесты.

Запрос: подтянуть фронтенд из `dev` и сохранить его визуал (он признан лучше), а логику оставить ту, что сильнее. Сильнее — логика каталога: серверная пагинация, состояния обработки, переиспользование viewer'а PDF, дескрипторы областей (см. ADR-0008). Логика `solar-ui.mjs` (парсинг произвольного JSON-паспорта в браузере) для каталога неприменима: объём конверта и число строк на статью исключают клиентскую обработку.

## Рассмотренные варианты

### A. Два экрана: `solar` как есть + мой каталог без изменений (выбрано)

- Плюс: визуал `dev` переносится байт-в-байт, без ручного воспроизведения; мои модули, контракт API, тесты и мок не трогаются; откат — один revert.
- Плюс: оба экрана решают разные сценарии: `solar` — быстрый разбор одного паспорта без сервера, каталог — пакетный прогон и доказательства.
- Минус: в продукте два визуальных языка и две точки входа; навигации между экранами нет.
- Минус: `solar-ui.mjs` — отдельный код без тестов, его поведение не связано с контрактом каталога.
- Цена: ~0,5 часа, риск регрессий минимален.

### B. Один экран: мой каталог, перекрашенный в визуальный язык `dev`

- Плюс: единый продукт, один визуальный язык.
- Минус: `style.css` и вся разметка `index.html`/`document.js` переписываются под чужие классы и токены; `solar.css` рассчитан на другую структуру (hero, stats, panel), а не на каталог с табами и пагинацией.
- Минус: визуал воспроизводится вручную, «как в dev» гарантировать нельзя; регрессии в доступности (skip-link, focus, `aria-live`) и в мобильных состояниях.
- Цена: 1–2 дня, высокий риск сломать уже принятый UI из ADR-0008.

### C. `solar.html`/`solar.css` как единственная оболочка, моя логика внутри

- Плюс: один экран, визуал `dev` сохраняется полностью.
- Минус: фактически переписывание `app.js`/`document.js` под чужую разметку: hash-роутинг, табы сущностей, пагинация, состояния загрузки/скана, диалог доказательств. Половина возможностей каталога в `solar`-разметке не имеет места.
- Минус: `server.py` и мок должны отдавать один набор модулей — рост связности.
- Цена: 2+ дня, риск потерять функции, за которые уже отвечает моя ветка.

## Решение

Вариант A. Экран `dev` переносится как отдельный, мой каталог остаётся основным на `/`.

- Файлы `static/solar.html`, `static/solar.css`, `static/solar.mjs`, `static/solar-ui.mjs` взяты из `origin/dev` без правок.
- `server.py`: мои маршруты (`/` → `index.html`, `/style.css`, `/app.js`) сохранены; добавлены `/solar`, `/solar.html`, `/solar.css`, `/solar.mjs`, `/solar-ui.mjs`. Ключ `/` **не** переключается на `solar.html`, в отличие от `dev`: это сохраняет поведение моей ветки и не ломает ссылки на каталог.
- `tools/mock_api.py`: статика отдаётся из `static/` по имени файла, поэтому достаточно алиаса `/solar` → `solar.html`; остальное работало и так.
- `README.md`: мой текст сохранён, добавлен раздел про экран «Паспорт статьи».

## Последствия

Что упрощается:

- Визуал `dev` доступен без переписывания и без риска для принятого UI каталога.
- Разделение ответственности сохраняется: `solar` не требует API и работает статикой, каталог требует сервер.
- Откат тривиален: удалить 4 файла и 5 строк маршрутов.

Что усложняется:

- Два визуальных языка и две точки входа без перекрёстной навигации; пользователю нужно знать адрес `/solar`.
- Дублирование части представления (таблица результатов, карточка, CSV) в двух реализациях: `solar-ui.mjs` и `document.js`/`catalog.js`.
- Статика в `server.py` описана явным списком `ASSETS`, значит каждый новый файл `solar`-экрана надо регистрировать руками.

Принятые компромиссы:

- Визуальное единообразие отложено: сначала фиксируем оба экрана, потом решаем, какой из них продуктовый.
- Логика `solar` (парсинг JSON в браузере) не переиспользуется каталогом и остаётся изолированной.

## План внедрения

1. Забрать 4 файла из `origin/dev` без изменений (`git checkout origin/dev -- static/solar.*`).
2. Добавить маршруты `solar` в `server.py`, не меняя `/` и обработчики API.
3. Добавить алиас `/solar` в `static_file` мока.
4. Обновить `README.md` разделом про экран и адреса.
5. Проверить: `unittest` (smoke), затем `GET` на `/`, `/solar`, `/solar.html`, `/solar.css`, `/solar.mjs`, `/solar-ui.mjs` на обоих серверах — все 200.
6. Точки отката: коммит переноса откатывается `git revert`; маршруты `solar` в `server.py` — отдельный блок, удаляется без последствий; сам экран не влияет на API.

## Риски и технический долг

- **Риск:** `/solar` не индексируется навигацией и может «потеряться» в демо. Смягчение: упоминание в README, позже — ссылка из шапки каталога.
- **Риск:** `solar-ui.mjs` без тестов; при правках визуала `dev` он может разойтись с `solar.html` (идентификаторы `[id]`). Смягчение: файлы меняются только вместе.
- **Долг:** два набора стилей и две реализации таблицы/карточки. Решение о слиянии в один визуальный язык — отдельный ADR после выбора продуктового экрана.
- **Долг:** `server.py` по-прежнему не отдаёт ES-модули каталога (`catalog.js`, `document.js`, `tracks/*`), каталог живёт на `tools/mock_api.py`; это ограничение существовало до переноса и не устраняется здесь.
