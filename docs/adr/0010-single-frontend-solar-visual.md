# ADR-0010. Единый фронтенд в визуальном языке `dev`

- **Статус:** принято
- **Дата:** 2026-11-20
- **Владелец:** Илья Б (frontend)
- **Связанные решения:** ADR-0008 (каталог и карточка), ADR-0009 (перенос экрана `dev`, заменено)
- **Область:** `static/`, маршруты статики, `README.md`. Контракт API не меняется.

## Контекст и проблема

ADR-0009 перенёс экран «Паспорт статьи» из `dev` отдельным документом (`/solar`) рядом с каталогом. Продуктовое решение изменилось: нужен **один** фронтенд, а не два. Визуальный язык `dev` при этом признан лучше, логика каталога — сильнее.

Значит, задача не «влить файлы», а совместить три вещи:

1. визуал `dev`: тёмный фон `#0e1518`, панели `#152024`, лаймовый акцент `#d5ff83`, крупный герой, сетка 1.6fr/1fr, скругления 14–20;
2. всю логику каталога из `feature/rag-frontend`: hash-роутинг, серверная пагинация, статусы обработки, вкладки карточки, диалог доказательств, дескрипторы областей;
3. функциональность `dev`, которой у каталога нет: импорт паспорта JSON без сервера, привязка локального PDF, CSV по прошедшим проверку строкам, разбор семи таблиц Solar.

Ограничение: UI-тесты (`tools/uitest/harness.mjs`, `e2e.mjs`) держатся за классы и `aria-label` каталога и карточки, поэтому логику и разметку нельзя переписывать «с нуля».

## Рассмотренные варианты

### A. Каталог остаётся приложением, визуал `dev` переносится в общий `style.css` (выбрано)

- Логика и контракт не трогаются: меняются стили и оболочка разметки.
- Визуал воспроизводится токенами и компонентами из `solar.css` (герой, сводка, панели, таблицы, бейджи, диалог).
- Функциональность `dev` переносится в новый модуль `passport.js` как маршрут `#/passport` в том же приложении.
- Минус: `solar.html`/`solar.css`/`solar-ui.mjs` удаляются, визуальная сверка идёт по `solar.css` в истории git.
- Цена: ~1 день, риск регрессий закрывается существующими UI-тестами.

### B. `solar.html`/`solar.css` как оболочка, каталог встраивается внутрь

- Плюс: визуал гарантированно совпадает, потому что это исходные файлы.
- Минус: в solar-разметке нет места табам, сущностям, пагинации, состояниям загрузки/скана и диалогу доказательств; фактически переписывание `catalog.js`/`document.js` под чужой DOM.
- Минус: UI-тесты перестают находить свои селекторы, их пришлось бы переписать вместе с приложением.
- Цена: 2+ дня, высокий риск потерять функции.

### C. Фреймворк и общий дизайн-система

- Плюс: единые компоненты на будущее.
- Минус: сборка, зависимости, переписывание viewer'а — прямо противоречит ADR-0008 и срокам.
- Цена: несоразмерна задаче.

## Решение

Вариант A.

- `static/style.css` переписан на токенах `solar.css`: те же цвета, шрифтовая шкала, герой с лаймовой точкой, сводка из трёх чисел, панели с `panel-head`, таблицы с липкой шапкой, бейджи статусов, тёмный диалог доказательств. Классы каталога (`.filters`, `.count`, `.results`, `.pager`, `.badge`, `.doc-actions`, `.tabs`, `tr.result`, `tr.detail`, `tr.target`) сохранены ради тестов.
- `static/index.html`: шапка в стиле `solar` (знак, бренд, контекст), панель действий (области, «Паспорт», загрузка PDF, демо, импорт JSON).
- `catalog.js` и `document.js` получили герой и сводку; структура фильтров, таблиц, вкладок и адресов не изменилась.
- Новый `static/passport.js` — перенос логики `solar-ui.mjs` на общие `el`/`fill` и hash-роутинг: демо-паспорт, импорт JSON, таблица + карточка, фильтры, CSV, привязка PDF. Разбор данных остаётся в `static/solar.mjs`.
- Удалены `static/solar.html`, `static/solar.css`, `static/solar-ui.mjs`; убраны маршруты `/solar*` из `server.py` и алиас в `tools/mock_api.py`.

### Карта переноса визуала

| `dev` | Единый фронтенд |
|---|---|
| `.shell` | `.wrap` (та же ширина 1320 / 100% − 64) |
| `.masthead`/`.brand`/`.mark`/`.context` | шапка каталога |
| `.hero` + `h1 span` | герой каталога, карточки, паспорта; лаймовая точка `.dot` |
| `.stats` | сводка прогона, документа, паспорта |
| `.workspace`/`.panel`/`.panel-head` | таблица + карточка паспорта, панели каталога и карточки |
| `.filters` | фильтры каталога, результатов, паспорта |
| `.status.passed/review` | `.badge.ok/warn` (класс `.status` занят строкой состояния) |
| `.row-button`, `blockquote`, `dl` | таблица и карточка паспорта |
| файл-кнопки | `.file` в панели действий и в герое паспорта |

## Последствия

Что упрощается:

- Один HTML-документ, один `style.css`, один роутер: каталог → карточка → паспорт.
- Визуал `dev` применяется ко всем экранам, а не только к одному.
- Функции `dev` (JSON, локальный PDF, CSV) доступны без отдельного сервера и без второй точки входа.

Что усложняется:

- `style.css` стал единственной точкой визуальных изменений: правка токенов меняет все экраны сразу.
- Логика паспорта живёт в приложении и обязана переживать правки роутера; добавлен маршрут `#/passport` и обработчик импорта в `app.js`.
- Часть представления дублируется по смыслу: таблица результатов карточки (раскрывающиеся строки) и таблица паспорта (выбор строки + карточка справа). Это разные сценарии, но стили общие.

Принятые компромиссы:

- Каталог и карточка остаются серверными; паспорт — локальный. Это осознанно: у них разные источники данных.
- Паспорт по умолчанию показывает демо-значения, как в `dev`; CSV и привязка PDF включаются после импорта.

## План внедрения

1. Переписать `style.css` на токенах `solar.css`, сохранив селекторы, за которые держатся тесты.
2. Обновить `index.html`: шапка, панель действий, импорт JSON, тёмный диалог.
3. Добавить герой и сводку в `catalog.js` и `document.js` без изменения структуры фильтров/таблиц/вкладок.
4. Перенести `solar-ui.mjs` в `passport.js`; маршрут `#/passport` и импорт JSON — в `app.js`.
5. Удалить `solar.html`/`solar.css`/`solar-ui.mjs`, почистить маршруты.
6. Проверка: `unittest`, `tools/uitest/harness.mjs` (43 проверки), `e2e.mjs` (15 проверок), скриншоты каталога, карточки, паспорта, диалога и мобильной вёрстки.

## Риски и технический долг

- **Риск:** визуальная сверка идёт по `solar.css` из истории git, а не по живому экрану. Смягчение: исходник доступен (`git show origin/dev:static/solar.css`), ключевые токены перенесены дословно.
- **Риск:** тесты опираются на тексты и классы; при следующей правке разметки их нужно обновлять вместе с ней.
- **Долг:** дублирование таблицы результатов и таблицы паспорта; кандидат на общий компонент после стабилизации сценариев.
- **Долг:** `server.py` по-прежнему не отдаёт ES-модули каталога и API `/api/documents`; рабочий путь — `tools/mock_api.py`.

## Обновление 2026-11-20 (по итогам ревью)

Два уточнения, принятые после код- и дизайн-ревью:

1. **Статус проверки в паспорте.** Импортированные `export.json`, `facts` и Solar не содержат `validation_status`. Поэтому статус выводится: замечания → «На разборе»; нет явного статуса, но `extraction_status: extracted` и замечаний нет → «Пройдена»; иначе «Ожидает». У выведенных строк есть подсказка и общий notice, что валидация не запускалась. Это возвращает CSV и сводку для форматов, которые обещает README, не выдавая выведенный статус за результат проверки.
2. **`server.py` отдаёт модули фронтенда.** В `ASSETS` добавлены `api.js`, `catalog.js`, `document.js`, `dom.js`, `evidence.js`, `passport.js`, `solar.mjs`, `ui.js`, `tracks/*`. Экран паспорта снова работает без мока; каталог и карточка остаются за `/api/documents` и запускаются через `tools/mock_api.py`.

Дополнительно: `#/passport` обрабатывается до проверки области (иначе `?track=solar` упирался в «раздел не подключён»); каталожная панель на паспорте скрыта; CSV переехал в шапку панели «Результаты» и стал вторичной кнопкой, импорт — единственный primary; статус импорта показывается inline под героем; фокус вкладок карточки ставится синхронно, без гонки с `focusView()`.
