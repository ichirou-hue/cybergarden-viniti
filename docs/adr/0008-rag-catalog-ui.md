# ADR-0008. RAG-каталог и карточка результата: контракт, состояния и план работ frontend

- **Статус:** принято (реализовано на заглушке `tools/mock_api.py`; backend Мити подключается заменой источника)
- **Дата:** 2026-11-20
- **Владелец:** Илья Б (frontend, RAG)
- **Связанные решения:** ADR-0001 (конверт и обработчики), ADR-0004 (хранение и статусы), ADR-0005 (CSV-экспорт)
- **Область:** `static/`, контракт API для UI. Код, тесты и конфигурация этим документом не меняются.

## Контекст и проблема

План команды закрепляет за Ильёй Б каталог публикаций и результатов, переключение области, предметные фильтры и состояние обработки; проверяемый результат — «пользователь находит нужные записи и понимает, что обработано, а что завершилось ошибкой». Дополнительно Илья Б отвечает за общее подключение frontend и переиспользование существующего PDF viewer, владеет `static/app.js`, `static/index.html`, `static/style.css` и координирует любые правки этих файлов. До нового крупного UI обязательны варианты прототипа и выбор пользователя.

Текущий интерфейс этого не даёт и не может дать малой правкой:

| Что есть сейчас | Почему не масштабируется |
|---|---|
| Одна статья на экран, выбор из `<select>` | Нет каталога: при 90 PDF и статусах «обработано / ошибка / частично» список не несёт информации о состоянии |
| Весь JSON статьи грузится в браузер, фильтрация клиентская | В `dev_gold` до 28 649 строк на статью (D014); конверт — десятки мегабайт. Клиентская фильтрация и рендер не выдержат |
| Замечания — фиксированный словарь из 4 кодов в `app.js` | В шаблоне замечание — строка `issues.csv` (`issue_id`, `check_name`, `description`, `record_ids`). Словарь кодов не покрывает предметные проверки и не даёт причины |
| `facts[]` плоский, одна метрика + k | Шаблон требует связей: конфигурация, набор, задача, эксперимент; для solar — прибор, материал, измерение |
| Viewer умеет «Стр.» и «Заголовок» (две подсветки) | В конверте пока один `source`; без якоря заголовка это регресс существующей возможности |
| Один `paper.id` (sha256) | `D001` двух областей — разные документы; без `track` в ключе UI смешает области |
| Нет представления статусов | Пакетный прогон 90 PDF не виден: пользователь не понимает, что обработано, что упало и почему |

Замеры, на которые опирается решение: 21 dev-PDF, 371 страница, 3 скана без текстового слоя; у скана `sources=0`, у текстовых статей 468–1194 фрагмента. Значит UI обязан честно показывать «страница без текста / скан без OCR», а не пустую таблицу.

## Рассмотренные варианты

### A. Расширение текущего стека: каталог + карточка + дескрипторы областей + серверная пагинация (выбрано)

- Плюс: нет сборки и новых зависимостей, работает офлайн, viewer переиспользуется, Егор подключает `tracks/solar.js` без правок общей обвязки, текущие загрузка/демо/экспорт сохраняются.
- Минус: `app.js` нужно распилить на модули (ES-модули без сборки), хэш-роутинг и состояния пишутся руками, UI-тестов нет — нужен ручной чек-лист.
- Цена: ~1,5 дня Ильи Б + 0,5 дня Егора; риск конфликтов в общих файлах снимается порядком PR.

### B. SPA на фреймворке (React/Vite)

- Плюс: удобные состояния, таблицы, роутинг.
- Минус: сборка и зависимости, переписывание viewer и загрузки, новая точка отказа на демо; прямо противоречит соглашению «UI не переписывать ради внешнего вида» и «не создавать два приложения».
- Цена: 2+ дня и риск, не связанный с критериями кейса.

### C. Серверный рендеринг страниц

- Плюс: минимум JS, каталог хорошо отдаётся с сервера, работает без клиентского состояния.
- Минус: фильтры, диалог доказательства и переключение области всё равно требуют JS; смешение с текущим `http.server` усложняет маршруты и дублирует разметку.
- Цена: средняя, выигрыш мал по сравнению с A.

## Решение

Вариант A. Один экран каталога, один экран карточки, один viewer. Дескриптор области описывает только представление (колонки, фильтры, вкладки сущностей), но не логику загрузки и не разметку.

### Информационная архитектура

Маршруты в hash (работают без настройки сервера, состояния шарятся ссылкой):

| Маршрут | Экран |
|---|---|
| `#/` | Каталог: область, поиск, статус, сортировка |
| `#/doc/<track>:<sha256>` | Карточка: публикация, вкладки, фильтры, таблица результатов |
| `#/doc/<track>:<sha256>?tab=entities&entity=configurations` | Сущности области |
| `#/doc/<track>:<sha256>?tab=issues` | Замечания проверок |
| `#/doc/<track>:<sha256>?tab=sources&kind=table` | Фрагменты PDF (существующий режим) |
| `#/doc/<track>:<sha256>/source/<source_id>` | Открытый viewer с подсветкой (глубокая ссылка) |

Параметры фильтров (`q`, `metric`, `k`, `dataset`, `config`, `status`, `issues=1`, `page`) живут в query — ссылку на выборку можно отправить проверяющему. Дополнительно: `result=<result_id>` подсвечивает запись (переход из «Замечаний»), `sq` — поиск по фрагментам, `entity` — тип сущностей, `kind` — тип фрагмента.

### Экран каталога

- Переключатель области: RAG / Solar (значение в `?track=`, по умолчанию RAG).
- Поиск по `publication_id`, названию, году, авторам (debounce 250 мс, отмена предыдущего запроса).
- Фильтр статуса: все / обработано / частично / ошибка / в очереди.
- Колонки: `publication_id` + название; год; страниц; результатов; замечаний; статус (бейдж с текстом, не только цвет); длительность обработки; действия «Открыть», «CSV».
- Баннер пакетного прогона: «обработано 37 из 90, 3 ошибки» + ссылка на список ошибок с текстом причины.
- Пустое состояние: объяснение, кнопки «Загрузить PDF» и «Открыть демо» (существующие).
- Пагинация 50 документов, серверная; сортировка по `publication_id` / статусу / числу замечаний.

Данные каталога — только сводка. Конверт статьи в каталоге не загружается никогда.

### Экран карточки

Шапка: `publication_id`, название, год, авторы, DOI, `in_scope` (+ причина исключения), статус, предупреждения обработки, ссылки «PDF», «JSON», «CSV (область)».

Вкладки: **Результаты** (по умолчанию), **Сущности**, **Замечания**, **Фрагменты PDF**, **Сводка**.

Панель фильтров (серверная): поиск, метрика, `k`, набор, конфигурация, `extraction_status`, «только с замечаниями». Для solar: прибор, материал, метрика.

Таблица результатов (RAG): метрика (+`@k`), значение (`normalized` + `raw`/единица), конфигурация, набор/задача, группа, статус, проверка, источник.

Раскрытие строки: `raw_value`/`raw_unit`, `normalized_*`, `result_origin` (primary/cited) и `cited_publication_id`, `duplicate_of`, `aggregation`, `sample_size`, `note`, цитата `source.fragment`, связанные замечания.

Источник — две кнопки, как сейчас: **Стр. N** (ячейка/строка значения) и **Заголовок** (ячейка с названием метрики и единицей, если она из таблицы). Вторая кнопка рендерится только при наличии якоря заголовка.

Вкладка «Замечания»: `check_name` + человекочитаемая подпись из словаря дескриптора, `description`, ссылки на `record_ids` (переход к результату с подсветкой). Неизвестный `check_name` показывается как есть — не скрывается.

Вкладка «Сущности»: таблицы по типам области со ссылкой «показать результаты этой конфигурации/прибора».

Поведение по статусам: `running` — баннер и блокировка экспорта; `failed` — текст ошибки и подсказка; `partial` — список необработанных страниц; скан без OCR — явный баннер «текстовый слой отсутствует, OCR не выполнялся»; ноль результатов — объяснение и ссылка на «Фрагменты».

### Контракт API (требуется от Мити)

| Метод | Назначение | Обязательные поля ответа |
|---|---|---|
| `GET /api/documents?track=&q=&status=&sort=&limit=&offset=` | каталог | `total`, `items[]`: `document_id`, `track`, `publication_id`, `title`, `year`, `pages`, `status`, `error`, `results_count`, `issues_count`, `scanned`, `ocr_used`, `handler_revision`, `duration_ms`, `updated_at` |
| `GET /api/documents/{doc_id}` | карточка без результатов | `publication`, `status`, `error`, `warnings[]`, `counts{results,issues,by_status}`, `run{handler,source_revision,model,duration_ms}`, `export{json,csv}` |
| `GET /api/documents/{doc_id}/results?q=&metric=&k=&dataset=&config=&status=&issues=&limit=&offset=&sort=` | таблица | `total`, `items[]`: `result_id`, `metric_name`, `metric_k`, `metric_value`, `metric_unit`, `raw_value`, `raw_unit`, `normalized_value`, `normalized_unit`, `extraction_status`, `result_origin`, `cited_publication_id`, `duplicate_of`, `aggregation`, `sample_size`, `note`, `config_id`, `dataset_id`, `task_id`, `experiment_id`, `source{page,section,table,figure,fragment,source_id}`, `header_source{...}\|null`, `issues[{issue_id,check_name,description}]` |
| `GET /api/documents/{doc_id}/facets?...` | счётчики фильтров | `metrics[]`, `ks[]`, `datasets[]`, `configs[]`, `statuses[]` — `{value,label,count}` |
| `GET /api/documents/{doc_id}/issues?limit=&offset=` | замечания | `total`, `items[]`: `issue_id`, `check_name`, `description`, `record_ids[]`, `source` |
| `GET /api/documents/{doc_id}/entities?type=` | сущности | `total`, `items[]` по полям области |
| `GET /api/documents/{doc_id}/anchors/{source_id}.png` | подсветка | PNG; 404 — viewer показывает цитату и номер страницы |
| `GET /api/documents/{doc_id}/anchors/{source_id}.json` | якорь для глубокой ссылки | `page`, `fragment`, `bbox`, `kind` — чтобы `#/doc/<id>/source/<source_id>` открывался без строки результата |
| `GET /api/documents/{doc_id}/sources?kind=&q=&limit=` | вкладка «Фрагменты PDF» | `total`, `items[]`: `source_id`, `page`, `kind`, `fragment` (допускается `quote`) |
| `GET /api/documents/{doc_id}/pdf` | ссылка «PDF» в шапке | файл `application/pdf` |
| `GET /api/documents/{doc_id}/export.json` / `export.csv` | выгрузка | файл, ссылка на скачивание |
| `POST /api/documents` (`X-Track`, `X-Filename`, тело — PDF) | загрузка | `document_id`, `status`; 415 на не-PDF |
| `POST /api/demo` | открыть демо-статью | `document_id` |
| `GET /api/jobs?track=` | прогресс пакета | `{state, total, done, partial, failed, items[{document_id,status,error}]}` |

Требования к контракту, без которых frontend блокируется: (1) `document_id` включает `track`; (2) сводка каталога не содержит результатов и цитат; (3) у результата два независимых якоря — значения и заголовка; (4) `issues` отдаются вместе с результатом, чтобы не делать N+1 запросов; (5) поиск на сервере покрывает те же поля, что сейчас ищутся на клиенте (метрика, `k`, значение, `raw_value`, контекст/набор, цитата, подписи замечаний), иначе это тихая регрессия.

Интеграция: пока backend не реализует `/api/documents…`, UI запускается через `tools/mock_api.py` (он же отдаёт `static/`). `server.py` — зона Мити — сейчас отдаёт только `/`, `/style.css` и `/app.js` и старый `/api/papers`; чтобы новый UI заработал на штатной точке входа, backend должен раздавать `static/**` (с той же защитой от `..`, что в моке) и реализовать таблицу выше. До этого `python server.py` показывает сообщение о запуске мока, а не молчаливый пустой экран.

### Формат дескриптора области

```js
// static/tracks/rag.js — только представление, без запросов
export default {
  track: "rag",
  label: "RAG",
  note: "Метрики поиска и ответов",
  filters: [
    {key: "metric", label: "Метрика", facet: "metrics"},
    {key: "k", label: "k", facet: "ks"},
    {key: "dataset", label: "Набор", facet: "datasets"},
    {key: "config", label: "Конфигурация", facet: "configs"},
    {key: "status", label: "Статус", facet: "statuses"},
  ],
  columns: [
    {key: "metric", label: "Метрика"}, {key: "value", label: "Значение"},
    {key: "config", label: "Конфигурация"}, {key: "dataset", label: "Набор / задача"},
    {key: "group", label: "Группа"}, {key: "status", label: "Статус"},
    {key: "check", label: "Проверка"}, {key: "source", label: "Источник"},
  ],
  entities: [
    {key: "configurations", label: "Конфигурации"}, {key: "datasets", label: "Наборы данных"},
    {key: "tasks", label: "Задачи"}, {key: "experiments", label: "Эксперименты"},
  ],
  units: {fraction: "доля", "%": "%"},
  issueLabels: {metric_scale_assumed: "Шкала принята по заголовку"},
};
```

Правила: дескриптор не содержит HTML и не ходит в сеть; отсутствующая подпись замечания не скрывает замечание; `tracks/solar.js` пишет Егор и не требует правок общих файлов.

Необязательные поля дескриптора, которые уже поддерживает `document.js`: `kinds` — подписи типов фрагментов, `fieldLabels` — подписи полей сущностей, `entities[].columns` — колонки таблиц сущностей, `entityFilters` — связь поля сущности с фильтром результатов (например, `config_id → config`), `cells` — переопределение рендера колонки, `units` — подписи единиц, `issueLabels` — человекочитаемые подписи проверок, `searchHint` и `emptyHint` — подсказки.

### Контракт viewer

`evidence.js` предоставляет `openEvidence({docId, source, sourceId, label, signal})`: если передан `source`, запрос за якорем не нужен; иначе якорь читается из `anchors/{source_id}.json`. Модуль открывает существующий `<dialog>`, показывает цитату, номер страницы и PNG по `anchors/{source_id}.png`, умеет глубокую ссылку и закрытие по Esc (нативное поведение `dialog`). При ошибке изображения — падение в «номер страницы + цитата», как сейчас. Дублирования viewer нет: вкладка «Фрагменты» и карточка результата используют один модуль.

### Производительность и доступность

Бюджеты: каталог на 90 документов ≤ 100 КБ и рендер < 100 мс; страница результатов 50 строк ≤ 150 КБ; конверт статьи в браузер не загружается; повторный запрос фасетов кэшируется на документ; поиск с debounce и `AbortController`. Доступность: `scope="col"` у заголовков, `aria-live` для счётчика, статусы текстом, фокус в диалоге, навигация с клавиатуры, читаемость при 200% масштаба.

### Структура файлов и владение


Статус реализации: F0–F3 закрыты на заглушке (`tools/mock_api.py`), F4 ждёт `tracks/solar.js` от Егора.

Владение: Илья Б — `index.html`, `style.css`, `app.js`, `api.js`, `catalog.js`, `document.js`, `evidence.js`, `tracks/index.js`. Егор — только `tracks/solar.js` и PR через Илью Б. ML-разработчики не правят `static/`. Порядок вливания: `api.js` + `tracks/index.js` → `catalog.js` → `document.js` → `evidence.js` (перенос без смены эндпоинта) → `tracks/rag.js` → `tracks/solar.js`.

## Последствия

**Упрощается.** Одна обвязка на две области; viewer один; добавление области — файл дескриптора; большие объёмы не упираются в браузер; статусы пакетного прогона видны; ссылка на конкретную выборку или источник шарится; существующие загрузка, демо, JSON-экспорт и подсветка сохраняются.

**Усложняется.** Появляется зависимость от контракта API (снимается мок-сервером на F1); `app.js` распиливается — нужен порядок PR и дисциплина «не править общие файлы параллельно»; фильтры и фасеты должны считаться на сервере, иначе 28k строк в браузере; JS не покрыт тестами — нужен ручной чек-лист регрессии на каждом этапе.

**Принятые компромиссы.** Без сборщика и фреймворка — модули на нативном ES, немного ручного состояния. Без отдельного дизайна — текущая визуальная система, меняется структура экранов и информативность. Каталог показывает сводку, а не превью результатов. Solar-дескриптор пишет не владелец обвязки.

## План внедрения

Часы — от начала согласованной работы, календарные (не чистое кодирование). Каждый этап заканчивается тегом `ui-stage-N`.

### F0. Спецификация и прототипы (0–2 ч) — блокирующий

- Спецификация RAG-каталога и карточки: поля, фильтры, состояния, что серверное/клиентское, стыки с Митей. Артефакт: `docs/requirements/rag-catalog.md`.
- Два прототипа (плотная таблица-каталог и каталог-карточки) → **выбор пользователя**. Без выбора F2 не начинается.
- Согласование с Митей списка полей из раздела «Контракт API» и правила «два якоря».
- **Готово, когда:** есть утверждённый макет и подписанный список полей; перечислены отличия от текущего UI.

### F1. Каркас на моках (2–8 ч)

- `api.js` (ошибки, отмена, единая обработка 404/422/500), `tracks/index.js`, `tools/mock_api.py` с 3–5 фикстурами (обычная статья, скан, 28k строк, ошибка обработки).
- `catalog.js` на моках: область, поиск, статус, пагинация, пустое состояние.
- Вынос viewer в `evidence.js` **без смены эндпоинта**, чтобы старый экран продолжал работать.
- **Готово, когда:** каталог рендерит 21 мок-документ, старый сценарий «загрузить PDF → открыть демо → подсветить» не сломан, smoke-тесты зелёные.

### F2. RAG-карточка на реальных данных (8–16 ч)

## Риски

| Риск | Влияние | Смягчение |
|---|---|---|
| Митя не успевает с контрактом API | Простой frontend | F1 на моках; список полей фиксируется в F0; мок повторяет контракт байт-в-байт |
| 28k строк в браузере | Зависание, провал демо | Серверная пагинация с F2; бюджет 50 строк/150 КБ; тест на D014 в чек-листе |
| Конфликты в общих файлах с Егором | Срыв интеграции | Егор правит только `tracks/solar.js`; порядок вливания; PR через Илью Б |
| Выбор прототипа затягивается | Сдвиг F2, главный путь 12–16 ч под угрозой | Прототипы готовы к концу 2-го часа; при отсутствии выбора — фиксируем вариант «таблица» и идём дальше |
| Замечания приходят только кодами | Непонятная причина на защите | Словарь подписей в дескрипторе + fallback на `check_name`; `description` от сервера обязателен |
| Нет JS-тестов | Регрессии незаметны | Ручной чек-лист (загрузка, демо, JSON, подсветка, пагинация, пустые состояния) на каждом этапе |

## Технический долг

- Хэш-роутер и состояния — ручные, без библиотеки; при росте сценариев потребуется пересмотр.
- Нет подсветки диапазона ячеек и нескольких прямоугольников в viewer (одна рамка на якорь).
- Нет сравнения статей и сводных графиков — вне рамок.
- Нет онлайн-обновления статусов пакета (только повторный запрос каталога); SSE/websocket — после хакатона.
- Нет UI-тестов; чек-лист ручной.
- `tools/mock_api.py` остаётся в репозитории как инструмент разработки и требует поддержки при изменении контракта.
