# Старт команды: общая платформа, две области

## Зачем и что уже есть

Делаем один каталог проверяемых результатов научных статей с двумя обработчиками: RAG интегрируем первым, solar разрабатываем параллельно. RAG — сведения о системах и экспериментах из статей, не чат-бот. Подробности и риски: [разбор кейса](requirements/2026-11-20-hackathon-case-analysis.md), [рабочий план команды](requirements/2026-11-20-team-plan.md). Текущие команды запуска, сценарий и описание работающего прототипа — в [README](../README.md).

Прототип уже извлекает набор RAG-метрик из PDF и хранит evidence/координаты в SQLite и JSON. Это не готовый общий контракт для двух областей: CSV, OCR, пакетная обработка solar и солнечный экстрактор отсутствуют. Точность на корпусе организаторов ещё не измерена.

## Данные и шаблоны

Комплекты участников доступны рядом с этим документом:

- Общий обзор: [case-overview.pdf](materials/case-overview.pdf)
- Solar: [solar-participant-kit.zip](materials/solar-participant-kit.zip)
- RAG: [rag-participant-kit.zip](materials/rag-participant-kit.zip)

Если эта папка размещена на Google Drive, скачайте нужные материалы оттуда. `Downloads` — только исходное место, откуда материалы были получены; для работы с ними локальный каталог Downloads не требуется. Распаковывайте два ZIP в разные каталоги: имена D/P повторяются между областями. Рабочие комплектные данные: `dev` — разработка, `dev_gold` — открытый эталон для оценки, `test` — итоговый набор. В каждом архиве есть README и 7 CSV-шаблонов; у RAG также `schema.json`. Запускайте `tools/check_submission.py` из соответствующего архива, команда и параметры приведены в разборе кейса.

## Распределение и первые задачи

Работа разделена на два тематических потока и общий backend. Первые задачи рассчитаны на 2–4 часа с начала работы. Общий контракт согласуют Митя и оба ML-разработчика до реализации интеграции. ML сначала приносят минимальный sample JSON из настоящей dev-статьи и обсуждают поля с Митей; не придумывают независимо API или endpoint. Пути для будущих файлов ниже — рабочие предложения, не утверждение, что такие файлы уже существуют.

Перед любым новым крупным UI обязательны варианты прототипа и выбор пользователя; сейчас документ фиксирует только организацию. Существующие `static/app.js`, `static/index.html` и `static/style.css` — общие файлы: Илья Б координирует интеграцию, Егор не меняет их конкурентно, а готовит обособленный solar-модуль и согласует подключение. PDF viewer один, переиспользуем существующий, не дублируем.

## Контрольные точки и ограничения

**Через 12–16 часов:** должен быть интегрирован сквозной RAG-путь на реальной dev-статье: связанные данные, источник в PDF, замечание и экспорт; solar — небольшой рабочий dev-набор через тот же общий конверт. Начать CSV-экспорт до этой точки. Измерить время обработки. Если solar не даёт достоверных связей, обозначить его экспериментальным, не подменять пропуски догадками.

Не обещаем качественный полный прогон 180 test-PDF за 48 часов. Качество, скорость, доступные квоты/модели и разрешённость передачи PDF внешним API не подтверждены. Текущий прототип ограничен PDF 20 МиБ и 150 страницами; OCR и солнечное извлечение не реализованы. Проверка шаблона не доказывает научную точность. Сначала оценивать на `dev`/`dev_gold`, фиксировать необработанное и проверять значения по источнику.
